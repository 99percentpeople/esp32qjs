# W-08 WPS Radio 所有权与 Station 配置恢复

接续 [原始错误与接收边界](2026-09-11-w08-wps-errors.md)，本批接入内部
Radio 操作。公开 Session/Future/watch、Station helper/runtime 接入及集中
运行验收仍待完成；本批不是公开 WPS 配网 API 的交付。

## 准入与持有

仅接受已启动、未连接 Station 的精确 helper lease 快照。APSTA 需要明确
允许 AP 信道中断；拒绝外部 owner、固定信道、待处理操作、Enterprise/
SmartConfig、未知 interval 及故障状态。新 lease、promiscuous 和 wake owner
不能在配网期间加入。APPLICATION/STA/AP 三个原 helper 在整个关闭期间保持
存活，普通 end_operation 不得提前释放 WPS operation。

内部 worker 分离 `prepare` 和 `start`：先在 Wi-Fi task 检查并取得 WPS
原生所有权、安装协商状态，再由 Radio 切换 RAM storage，最后启动协商。
原生准入拒绝时不切换存储、不重写 Station 配置或信道。没有执行 receipt
的未知交接保留 worker/Radio 所有权，不推断为可重试或可释放。

## 配置与关闭顺序

开始前保存 Station 全量 SDK 配置、当前实际信道和已知存储策略。配网的
临时 Station 写入使用 RAM，不把协商配置写进 Flash。finish_capture 保留
凭据，close 清零凭据；两者均先完成原生停止与 timer/native 排空，再：

1. 确认 Station 已断开，在 RAM 下恢复原配置，使用现有 semantic comparator
   读回核对公开字段，临时读回中的秘密随即清零。
2. 恢复原信道并读回核对。
3. 恢复原存储策略；失败将 Radio 的 storage knowledge 标成未知，并保留
   operation 和快照，只重试尚未完成的恢复步骤。
4. 向默认事件循环投递带精确 operation identity/generation 的 boot marker，
   等待确认后才交付凭据或释放 Radio owner。队列满保留关闭状态，稍后重试；
   不在事件 callback 中等待 Radio mutex 或调用 driver。

PIN 可在协商期间读取；凭据须等上述捕获关闭、恢复及事件确认完成后再
copy/commit。最终释放清零整个绑定对象，包括原 Station 凭据和读回 scratch。
本次恢复配置不自动恢复旧连接，也不连接新凭据；后续公开 API 需要明确
连接策略并通过 Station helper 实施。
