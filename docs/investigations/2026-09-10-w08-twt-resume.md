# W-08 individual Agreement resume

`WiFiTwtAgreement.resume({ timeoutMs? })` 已接入唯一 v1，保持 Candidate。
这是对暂停协议的显式恢复请求，复用现有信息操作的 Radio lease、数字身份、
TX 记录和关闭流程。完整广播协议、物理故障恢复及阶段/实机验收仍未完成。

## 原生语义与完成边界

固定 SDK `fff9895c82` 的公开 suspend API 将 0 ms 编码成不带 wake TSF 的
无限期暂停。实际 `ieee80211_itwt_information` 支持 size=3、delay=0：选择
当前 TSF 或下一个合法 service period 并发送 Information 帧。此次 resume
通过既有 native queue 与该原生 producer 提交这一帧，没有用 1 ms 暂停替代，
也没有只修改本地 bitmap。原有 producer/TX/PM hooks 保持有效。

恢复准入核对同一 Agreement/request/flow/node，排除重协商、正在关闭、未知
或包含其他 flow 的 timer。旧自动恢复 timer 在替换帧发送中仍有效；只在
成功 TX callback 的原生路径中 disarm/done 后安装新 timer。回调排队中的
旧 timer 携带旧数字身份，不能处理新 payload 或完成新的 Future。替换失败
保留原始错误与资源，不进行未经确认的发送重试或 RF 状态回滚。

新的 timer identity 在精确 TX callback 内绑定到信息操作。发送成功先记录
txComplete，resume Future 继续等待实际 native timer process 完成、本地
timer 清理成功，并复核原 flow 仍建立且 suspend/resume bitmap 都已清除。
这是本地调度恢复证明，不是 AP 收包或 RF 唤醒证明。中间 suspend 观察事件
可以先交付；该事件不会被当作 resume 完成。先前 timer 错误不会被后到的
成功观察覆盖。native refresh 将等待中的关联/timer 失败保留为终态错误。

timeout/cancel 不撤回已发送的信息帧或取消已接受的恢复 timer。协议、TX 与
timer 存储不借用 Future/JS 对象。close/GC/runtime teardown 仍先退休信息
TX，再走原 Agreement teardown/timer 清理；旧数字通知不能作用于后续操作。

## 省电策略

归档中的 `he_twt_information_resume + 0x32` 在 `pm_get_sleep_type()==0`
时调用 `pm_set_sleep_type(1)`。同一 setter 也是 `wifi_set_ps_process` 的
实际策略写入，而且写 NONE 可能触发全部 TWT teardown。因此不能通过临时
开关 PS 再恢复前值来伪装无副作用恢复。

本次在托管 setup 的原生准入、定时 suspend/resume 准入及 timer 执行前核对
已启用的省电策略；NONE 时明确失败，不静默启用。setup dwell 完成也存在
相同的默认启用路径，所以在实际 driver mutation 前拒绝托管 NONE 来源。
用户需在创建 Agreement 前显式选择省电策略。此结论来自固定 SDK 调用链，
新增生产路径用例仍按用户要求后置，没有把静态分析写成实机复现。

正式注册、类型、manifest、API 和 SDK map 同步。`resume` 的 timeoutMs 为
1..60000，缺省 6000；长 service period 可以超过公共等待期限。
`wifi.twt.status().information` 新增 operation、txComplete、resumeComplete。
公共语义、错误与截止时间副作用见 [API](../api/wifi-twt.md)。

C5 HE、C5 no-SoftAP、C5 Wi-Fi-disabled、C3、S3 五个生产构建通过；manifest
为全项目 53 classes / 519 functions，严格类型、MQuickJS 与生成物一致性
检查通过。最终 ELF 核对 resume→Radio→native producer、timer 绑定/真实处理/
结果通知链，以及已有 recycler 的 IRAM/ROM 闭包；共享 SDK 和本地 archive
patch 不变。记录见 `build/w08-twt-resume-evidence.json`。

信息操作延迟 INTERNAL 账本从 112 B 增至 116 B，保存精确 timer identity；
Agreement Future state 从 264 B 增至 272 B（可用 PSRAM）。Radio owner、
TX identity、timer 表和 JS holder 预算不变；这不是实机 heap 基线。

生产 information/result、TX、timer 与 SDK admission fixture 已补等待恢复、
旧 timer、错误身份/任务、PS NONE、只读替换准入与保留错误用例；相关 fixture
依赖已更新。仅 AST 检查，未导入、编译或运行。完整 Future core、GC/OOM、
实际 native timer/TX 调度、长 service period、故障恢复、RF 和内存基线仍为
not-run，留到全部 Wi-Fi API 后集中验证。长 soak 仍留到 BLE 后。
