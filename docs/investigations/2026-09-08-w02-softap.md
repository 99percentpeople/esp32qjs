## 实际范围

新增 `wifi.startAP(options)` / 无参数 `wifi.stopAP()`，唯一 v1。当前仅独占、
冷启动、2.4 GHz channel 1–11 的 SoftAP，open 或 WPA2-CCMP。支持 ssid/password、
channel、hidden、authMode、maxConnections；未知字段、NUL、字节长度越界、
非整数/越界数字、认证与密码矛盾在资源/driver 工作前拒绝。SSID 1–32 字节，
密码若提供为 8–63 字节；maxConnections 1–4。默认 beacon interval 为 SDK 的
100 TU，未把该单位误标成毫秒 API。5 GHz、WPA3/PMF options、APSTA 热加入、
AP/CSI/ESP-NOW 共存、apClients/deauthClient 仍未接入。

AP 有真实 WIFI_AP lease，`radio.clients.wifiAccessPoint` 可见；AP 存活时拒绝
新的 application/STA/其他 feature owner。开始前必须显式结束旧连接、关闭 feature
并调用 wifi.stop。停止 AP 不通过强制关闭别人的 owner 实现。当前 startAP 返回
已接纳的配置与 driver started 状态；DHCP/IP readiness 查询 net.status，未声称
客户端已经可以通信。返回对象 OOM 后 AP 可能已运行，可以查 owner 并 stopAP。

## SDK 依据与实现顺序

固定 SDK `components/esp_wifi/include/esp_wifi.h` 的 set_config 契约要求接口已启用。
运行 STA 时先切 APSTA 再写配置会在配置提交前启用 AP，因此本批拒绝此类调用。
Radio 的 reserve_ap 在 mutation mutex 内先核验停止状态、零 owner、无 operation/
生命周期事务，再占用精确 AP lease；整个资源准备阶段都阻止其他 owner 进入。
写 RAM 配置前初始化 driver、启用 AP mode，set_config 成功后才 start；配置失败
不会提交 start。失败保留实际 driver ownership/原始 fault（包括 ap-config），
需要 stopAP/runtime cleanup；NVS/native init 清理不确定仍要求设备重启。

`components/esp_wifi/src/wifi_default.c` 的默认 AP 创建 helper 对 netif 分配使用
assert、对 attach/handler 注册使用 ESP_ERROR_CHECK。本批不调用该组合 helper，
而是逐步 esp_netif_new、attach_wifi_ap、set_default_wifi_ap_handlers 并检查返回值。
准备阶段失败自动走生产清理，避免 OOM 断言重启；没有在配置/资源验证前发 beacon。

stopAP 先以精确 AP token 获取生命周期排他，再释放 AP lease、quiesce driver。
排他一直保留到默认 netif driver/handler 脱离、netif 释放和 Radio shutdown 完成，
不会让新 owner 在旧 AP storage 尚未退出时重新初始化。SDK stop/deinit/监听器注销
失败保留准确后缀。runtime teardown 共用此路径，下一 runtime attach 重试未完成
清理，失败时拒绝 attach；不保留 JSContext/JS roots。

固定 SDK 的 disconnect_and_destroy 即使 esp_netif_set_driver_config 返回错误，
仍会调用 esp_wifi_destroy_if_driver。重复整个 detach 可能重复释放 driver，所以
该边界出现错误时锁存 s_ap_detach_error，保留 netif/排他，并在 WIFI_AP_FAILED
的 details.restartRequired 报告设备重启要求，不宣称 runtime restart 可以恢复。
这是 AP cleanup 诊断，与 radio.restartRequired 的 driver-init 诊断分开。

临时 wifi_config_t 和 JSCStringBuf 走已有 secure-zero；错误、结果和日志不带密码。
公开错误包含 operation、stage 与原始 espCode。API 返回值和错误 details 都有 GC
roots；新增生产 VM 测试覆盖移动 GC/第 N 次分配失败。
