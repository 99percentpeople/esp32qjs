# W-08 FTM responder offset 与启动前恢复

承接 [FTM 公开 Session](2026-09-10-w08-ftm-public.md)，新增
`wifi.ftm.setResponderOffsetCm` / `responderOffsetStatus`，正式契约见
[FTM API](../api/wifi-ftm.md)。firmware HEAD 为 `d7db8d1`，固定 SDK 为
`fff9895c82d744c7237be8847347bdd1b07c6643`。本批仍为 Candidate，运行验收未执行。

## SDK 依据与准入

固定 C3/S3/C5 的 public wrapper 检查初始化和 AP mode，再通过同步
`esp_wifi_ipc_internal` 调用 local wrapper。local wrapper 读取有符号 int16，
`ftm_responder_set_offset` 计算并写入唯一 T1 correction scalar，返回成功。
三目标 object 反汇编保存在 `build/w08-ftm-offset-esp32*-*.txt`。未修改共享 SDK，
没有把归档代码检查当成 IPC 调度或 RF 实测。

SDK 没有公开 getter。框架只记录原值为未知、已接受值、最后请求值、原始错误、
generation 和不回绕 revision；不猜默认零，不做未知前值回滚。SDK 调用前先标记
uncertain；失败保留旧 accepted history，显式重写成功后恢复 known。

公开输入只接受整数 -32768–32767 cm。Radio 在 mutation mutex 下检查健康、
完全停止的 AP/APSTA、零 lease/wake owner、无 promiscuous/rate lease、无
operation/lifecycle，随后读取实际 mode 才写入。SDK 调用不在 critical section。
本次 result 与 offset record 同锁复制后转换成 JS，错误或 OOM 不撤销 SDK 副作用。
现有 record getter 无 SDK 调用，供分配失败后重新观察。

## 恢复与生命周期

复用既有 `s_policy_restart` 的精确 lifecycle owner、mode、物理 generation 和
中央 cleanup，不另起恢复协调器。prepare 先冻结 known/current offset；存在
uncertain、过期 history、revision 耗尽或没有 AP 的恢复 mode 时拒绝。实际
physical deinit 成功后撤销 live knowledge，保留 accepted history。

pre-start replay 在 SDK AP mode 已配置而 AP 尚未运行时写入；完成位只在成功后
推进。后缀重试核对当前 generation/value 后跳过已接受写入。下一物理 generation
清除完成位，重新写入；post-start 阶段拒绝未完成的 pre-start offset，不迟到写入
已能接受 FTM 请求的 AP。没有扩展已知仍不支持的完整 restart 来源。

固定三目标的 setter 只修改独立 T1 correction，不改 STOP snapshot 中的信道、
功率、PHY 或 inactive time；因此加入已审查的 STOP-neutral 写入清单。其他目标
保留保守失效行为。offset 自身的 uncertain/capture/replay 条件仍单独检查。

## 角色注册与契约

namespace/capabilities 移到独立 module translation unit。initiator 编译项控制
start/status/Session/Future；responder + SoftAP 编译项控制 offset 两方法，二者
不互相要求。CMake ROM 生成器增加相同 responder/SoftAP SDK gate；仅有 responder
时不注册 initiator 空方法或 Session 类，limits 为零。类型把角色方法标为可选。
完整角色组合的固件矩阵留到 Wi-Fi 阶段验收，不把当前双角色 C5 编译当成全矩阵通过。

源类型、manifest、02、剩余表、API 文档和 SDK map 同步更新。FTM 缺失/歧义
终态的物理恢复仍待实现；其他 W-08/W-01～W-12 目标保持原范围。
