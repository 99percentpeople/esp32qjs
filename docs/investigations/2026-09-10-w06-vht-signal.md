# W-03/W-06：共享 VHT SIG 解码与 CSI MU/SU 修正

firmware `d7db8d1` 未提交工作区，SDK `fff9895c82`。前批 HT-SIG 工作已完成；
本批修正源码审查确认的 VHT 解码问题并补 Monitor 的 VHT 字段。没有执行缺陷
复现 fixture，因此这里记录的是源码修正与构建证据，不是运行修复验收。

## 原因与实现

旧 CSI helper 将两位 CBW 的所有非零值映成 40 MHz；HE target 又在解码前将
VHT 与 VHT_MU 合成同一 PHY，导致读取 MU word 中并非 SU MCS 的位置。

新增无 SDK/VM/分配依赖的 `esp32_mquickjs_wifi_rx_vht_signal.h`，CSI 与 Monitor
共用生产解码函数：

- CBW 0/1/2/3 分别报告 nominal PPDU bandwidth 20/40/80/160 MHz。160 不提供
  连续/80+80、中心频点或本机接收跨度信息，不提升硬件能力。
- 保留 SDK 原始 VHT_MU 分类到 CSI 解码调用；同时核对 word 的 Group ID。
  非 MU 分类且 Group ID 为 0/63 才有 SU 字段资格；SU MCS 仅 0–9 可用。
  MU/保留 MCS 清除旧 MCS 值与 availability，不把上一包结果留给下一包。
- STBC 和 SGI 是共用信号字段；SU coding 只有 SU 资格才可用。Monitor JS 与
  wire 共用相同 helper，MU 的 MCS/FEC 保持 null/unavailable。AMPDU count、
  aggregation、antenna 仍无 VHT SIG 来源，不从初始值制造事实。
- CSI 目前只保存既有 MCS/bandwidth/STBC，没有增加帧槽存储字段。VHT LTF
  分支拒绝未知 SU MCS；80/160 不再误用 40 MHz 的 subcarrier layout。原始
  样本保留为 unknown layout。显式 force-legacy-LTF 仍沿用其独立 LLTF 分支。
- Monitor HT 与 VHT availability 互斥，避免混入另一格式的可选字段。公共
  wire 继续使用既有 v1 flags/offset，Host decoder 无须新增格式。CSI 正式
  bandwidth 类型同步允许 80/160；所有 callable 与注册数量不变。

布局依据是固定 SDK 私有 `esp_wifi_vht_siga1_t`（CBW[1:0]、STBC[3]、
Group ID[9:4]、SGI[24]、SU coding[26]、SU MCS[31:28]）。字段含义交叉核对
[MathWorks VHT-SIG-A 文档](https://www.mathworks.com/help/wlan/ref/wlanvhtsiga.html)
和 [Radiotap VHT 的 SU/MU Group ID 定义](https://www.radiotap.org/fields/VHT.html)。
这不替代目标 SDK ABI 或 RF 输入资格验证。
