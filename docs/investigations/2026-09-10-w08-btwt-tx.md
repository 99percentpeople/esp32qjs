# W-08 广播 setup TX 身份与连接关闭撤销

本批将广播 setup 接入现有生产 TX ledger，替换 callback 19 对广播分支的
无条件转发。广播 RX 的 dialog/请求关联、原生结果 owner、Agreement 与
联合退休仍待接入，未注册 setupBroadcast。

本记录中“广播发送至少 20 B、拒绝保护布局”的初始假设已由
[后续 builder/RX 审计](2026-09-10-w08-btwt-rx.md)修正：实际广播长度为 15 B，
当前实现读取有效 IE，并以同步值副本适配 PMF 完成。下文保留本批历史边界。

## 固定 SDK 与缺口

固定 SDK `fff9895c82` 的 ieee80211_btwt_setup：在 +0x80 检查已建立的广播
bitmap，但未预留等待发送/响应中的 ID；+0x1cc 写共享 ID 的 response timeout，
然后 +0x216 进入 ieee80211_send_action。重叠请求不能只在 TX 完成后拒绝。

原广播 TX callback 从完成帧读取 ID，发送失败清除 bitmap 并发布失败观察；
发送成功复制 17 B 参数并安装响应定时器。上一批只保护了后面的 timer queue，
没有保护这个可以重新安装 timer 的发送完成入口。原广播 callback 固定按
24-byte MAC header 解析，另处理 EB flag 0x2000 的 8 B native prefix。
这些为归档/源代码证据，不写成已执行的调度竞争复现。

## 生产变化

- output 前校验 SDK category/action、TWT IE、dialog、command、长度和当前
  关联 node；原生保护布局与回调不一致时拒绝，不清除 PMF 或改写保护策略。
- 在既有 64 槽 TX ledger 内保存精确数字 identity、node 地址值、17 B 参数
  副本和 dialog。完成只领取同一 live EB 一次，匹配参数/当前关联、调用 task、
  timer 可用状态后才进入原生广播 callback。未知/重复/回收中的 EB 不转发。
- callback pin 保留 ledger 至原生调用返回。原生 callback 即使同步回收并
  改写 EB，wrapper 返回后也只访问已保留的 ledger，不再读取 EB。
- 连接 PM teardown 的 close_all 包装在退休广播 timers 前撤销所有现存广播
  TX 的执行权限；旧 TX 仍保留到 native recycler 完成，node/EB 地址复用不会
  让这批已撤销记录重新获得执行权限。
- 新广播 producer wrapper 在 SDK 写共享 response timeout 前检查同 ID 的
  TX 记录和 timer 活跃/保留 handle/发布 pin，拒绝重叠请求。后续公开 setup
  caller 尚未接入，这个 producer wrapper 目前仅在 object/archive；实际 ELF
  已接入的是 output/callback/close 链，不能据此宣称公开建立流程完成。

广播和 information 共用可选 identity union：两种记录在 C5 都为 24 B，
64 槽仍为 1536 B INTERNAL，TX 主账本仍为 768 B、静态对象仍为 48 B。
首次广播发送现在也会触发这块延迟分配；两种能力同时使用不重复分配数组。
回收路径仍不分配、不调用 driver、不访问 PSRAM。故障和 revision 耗尽保留
既有诊断政策，不因 runtime restart 清空而重新使用旧数字身份。
