# W-04：停止态 APSTA 临时速率与 Station 清理责任

基于 firmware `d7db8d1` 未提交工作区，SDK 保持 `fff9895c82`。公开 AP rate
Session 从 AP-only 扩展到已配置、停止、零 owner 的 APSTA 来源，沿用唯一 v1
参数与共用事务，不增加另一种 Session 或隐式切换 driver mode。

## 行为与所有权

- 原生 begin 在 Radio mutex 内解析并返回保存的 AP/APSTA mode，同时取得
  lifecycle。start 显式接收该 mode，在写速率前核对原生模式，Raw lease 的
  required_mode 保留完整 APSTA，START 后再次核对。不由一次较早 status 读取
  决定模式，不把 APSTA 降成 AP。
- runtime 在同 token 下退休旧 Station helper；APSTA 再准备 Station helper，
  然后准备 AP helper、借用 AP rate 并启动。两个 helper 都没有独立取得其他
  Radio owner。框架和固定 SDK 的 STA_START handler 仅推进启动状态/netif，
  本路径不调用 connect、不改变保存的 Station 配置或 Station 速率记录。
- 原生清理接受 required_mode 为 AP 或 APSTA 的精确 Raw owner。完成 STOP
  和 AP rate 恢复后仍原子交换成 lifecycle；runtime 退休 AP helper、Station
  helper，最后释放 token。驱动保留停止的原模式，不自动连接或重新启动。
- 运行中的共享 Station/AP、其他 owner、未知速率前值或故障来源仍不准入。
  这不是在维持现有连接的同时改 AP rate；SDK setter 仍在 START 前执行。

## 一并修正的失败清理

源码审查发现上一批 AP-only 路径先调用 Station helper retirement，但该步骤
失败后，close 只退休 AP helper 并 finish lifecycle，缺少对失败 Station 清理
的明确保留。本批新增 context.station_cleanup_pending：在初次 retirement 或
APSTA prepare 前置位，只有实际 retirement 成功后清除；close 必须重试尚未
完成的 Station 后缀，失败时继续保留 context/lifecycle/lane。

该标记也覆盖 Station prepare 的部分分配/注册失败，已完成的 AP rate 恢复不
重放。物理恢复仍由中央协调器退休两个旧 helper；原 Session 收到已经证明的
nativeTerminated 后只清空自己的 context，不关闭随后重建的 AP/Station helper。
这是一项源码路径修正，尚未执行故障注入，不能标为运行时复现与修复验收通过。
