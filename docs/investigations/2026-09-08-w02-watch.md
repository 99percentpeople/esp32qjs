# W-02：Wi-Fi 事件订阅与有界分发

基线 firmware `d7db8d1`，SDK `fff9895c82d744c7237be8847347bdd1b07c6643`。
这是工作区实现增量，不是提交、W-02 完成或全量事件 payload 验收通过。
正式契约见 [wifi API](../api/wifi.md) 和 `.d.ts` 中的 WiFiWatchOptions/WiFiEvent。

## 完成与观察的次序

原有 Station helper 在 ESP default-loop callback 内提交 native 状态与 Future
结果，timer callback 保留 native timeout obligation。新增 watch 不改这些完成队列。
对于 STA_START、STA_DISCONNECTED、SCAN_DONE，control mask 在 helper 注册前置位，
使通用 observer 跳过这些 ID；helper 在提交 native 状态之后调用 capture。
所有 helper handlers 注销且已进入 callback 退出后才清 mask。无 helper 时由
通用 observer 捕获这些事件。初始化/退休交界的观察允许丢失，不用于控制正确性。

scan/disconnect 的 generation 在唤醒 Future **之前**捕获，避免 runtime 已经
结束旧操作并启动新操作后把旧事件绑定到新 generation。运行时 poller 只在同代
native Future registration 已结束后分发；不递归调用 Future poll，也不等待观察
队列来释放 native obligation。Future finish 与 poller 都在同一个 runtime task
顺序执行，因此观察分发不会插入 finish 的中途。STA_CONNECTED 是关联事件，
不等价于已获得 IP；connect Future 仍保持原来的 IP-ready 完成边界。

## 存储和关闭

- 最多 4 个 live source；每个 EventQueue 容量 1–64，默认 16，drop-newest。
- 共享入口固定 32 个纯值快照，callback 对 source mutex 使用 try-lock，发送不阻塞；
  不调用 JS，不保留 SDK payload 指针。入口拥塞/锁竞争计入饱和 uint32 drop 计数。
- source 记录订阅时的 sequence 下界，不接收此前仍在入口内的历史事件。每订阅
  独立过滤事件名，单个队列满不会影响其他订阅者或 native Future。
- 单个快照只保留 2 个 uint64、ID/generation、flags、MAC、32-byte SSID 和
  4 个 scalar；不复制 SDK padding/union/secret。具体 sizeof/heap 需阶段构建账本验证。
- close/GC/runtime teardown 在 source mutex 内摘除 source；callback 对 runtime
  的最后使用也受同一把 mutex 保护。最后一个 source 关闭时删除 native ingress。
- queued snapshot 包含自身 raw-request flag；converter 不访问 source opaque。
  因而关闭后仍能按已有 EventQueue 契约转换队列/已接收 Future 中的事件。
- 一个静态 mutex 和一个 default-loop observer 是有意保留的 boot-owned 元数据。
  后者参数为 NULL，只访问静态 broker，不持有 runtime/JS/Radio lease 或 driver
  引用；watch 可以在 Radio 未启动时建立，也不阻止 Radio stop/shutdown。
- 所有 options 先验证；JS 队列构造失败归还 source，入口分配失败 dispose 已创建
  的队列。没有通过 raw export 创建 ByteView，因此也无新 retained pool。

`wifi.status().watch` 与 `queue.stats()` 分别报告共享入口和订阅队列丢弃；
`capabilities().features.watch` 与共享 admission limits 同步更新。
sequence 上限为 JS 精确整数最大值，达到后停止接纳新事件/订阅，不回绕复用。

## 必要检查与后续验收

本批执行 immutable C5 Context 编译、MQuickJS syntax、API manifest/feature 文档
及 recorded SDK map 一致性检查。日志与源/产物 hash 见
`build/w02-watch-evidence.json`。编译没有证明 callback 竞争或 RF 正确性。

按用户要求，Host C/Python、故障注入、三目标与 feature-disabled 全矩阵、实机功能
在 Wi-Fi APIs 完成后集中执行；长时间 soak 留到 BLE API 完成后。以下均为 not-run：

- watch 先于/晚于 STA helper 注册，scan/disconnect 结束时 ingress/subscriber
  都满，Future 仍结束；暂停 native callback 后启动新 Future，旧 generation 不误绑定。
- 多订阅过滤隔离、订阅关闭/GC 与 callback 并发、最后关闭释放入口、新订阅排除
  旧入口事件；关闭后 drain 已保存事件、runtime restart 不访问旧 runtime/source。
- 每个 JS/native 分配点失败与移动 GC、sparse/重复/越界/NUL 参数，sequence 与
  dropped 耗尽，无法注册 listener/poller 的诊断。
- 53 个 descriptor 对固定 SDK inventory 一致，已审查字段按实际生产 converter
  验证；将敏感和未知事件 payload 置为不可读内存，证明未解引用/未泄漏秘密。
- C3/S3/C5、Wi-Fi disabled、CSI disabled、SoftAP disabled 编译与 phase 状态一致性。
- 实机连接/断开/扫描/AP 客户端和事件饱和；不擦除 workspace，不做 soak。

高级 typed converter、raw schema/ByteView owner、FTM/TWT/NAN 等专属 session
仍属于后续任务；元数据可观察不等于高级功能已实现。
