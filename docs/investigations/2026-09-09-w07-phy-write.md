## 输入与原生事务

四个方法要求 interface/config 两个参数。协议数组复用原 wifi.configure 的生产
capture，完整唯一名称集合，不接受 maximum-protocol 简写、重复/空/稀疏数组、
NUL 后缀或强制类型转换。带宽严格为整数 20/40 MHz。复数对象允许且至少提供一个
对应频段字段；未知字段拒绝。JS getter 在 capture 阶段取值一次，原始异常保留，
对象/value 通过 GC ref 保持存活；原生阶段只保留复制后的标量。

Radio mutation mutex 内要求已初始化、storage 已配置、fully stopped、接口已在
mode 中启用、零 lease/wake/operation/lifecycle/promiscuous/临时 rate obligation，
且无 fault/cleanup/restart-required。不隐式 stop、不关闭其他 owner、不转换 mode。

单数形态在 mutex 内读取真实 band mode；AUTO 拒绝，5 GHz-only 将单值映射到
5 GHz slot。复数指定的频段必须实际启用且 target 支持，避免 SDK 忽略无效字段。
复用现有 snapshot_controls/apply_controls/restore_controls 与 PHY validator；
快照覆盖目标接口的所有 active bands，未指定频段原样保留。协议变化保留带宽，
带宽变化保留协议；HT40 与不支持它的协议组合在写入前拒绝。

首次写入前同时验证前值可准确重放，包括协议 prerequisite bits 与带宽。共享
writer 使用 20 MHz 过渡、写协议、写最终带宽；最终读回核对所有 active bands。
这是停止状态下的配置过程，不代表 RF 状态测量。成功返回对应 getter 的形态，
复数返回包括未修改但保留的 active band。

任何写入步骤失败，均尝试重写并读回验证旧协议/带宽。保留原始失败和独立 rollback
错误；成功回滚仍返回原始错误。回滚失败设置 phy-rollback 清理故障并阻止新 owner。
Flash storage 下 persistentMutationPossible 为真，RAM 读回不能证明旧 NVS 内容，
失败时即使运行配置已恢复仍保留 fault。普通 setter 不绕过此故障；后续独占物理
恢复属于尚未完成的生命周期任务，runtime restart 不能自动等同于恢复。

WIFI_DRIVER_WRITE_FAILED.details 含 interface/espCode/stage、mutationAttempted、
rollbackAttempted/Complete/Stage/Error、persistentMutationPossible。原生记录复用
wifi.status().radio.configuration；无配置/凭据对象或新恢复队列常驻。成功写入先于
JS result allocation，OOM 后应先读 getter/status 再决定是否重试。
