# W-08：Enterprise stop 的精确交接和清理后缀

基线 firmware `d7db8d1`、SDK `fff9895c82d744c7237be8847347bdd1b07c6643`。
接续 [Enterprise 公共入口](2026-09-10-w08-eap-public.md)。本轮接入原有
`wifi.stop()`，不新增公共方法；完整 restart 恢复策略和共存仍保留在总清单。

## 实现

已安装 Enterprise 时，过去普通 lifecycle 准入始终拒绝，用户只能先 disable。
现在 idle、已断连的 Station 可以直接 stop；已连接、pending Future、wake lock
或 foreign owner 仍按原有 stop 契约拒绝，不隐式断开 Station。

1. runtime 预留配置 owner 的精确 DISABLE token，固定 profile 引用。AP helper
   验证自己的 coordinator/cleanup 状态，再进入专属 Radio stop 准入。
2. Radio 在同一个 operation mutex 内校验 EAP binding/generation、全部原
   application/Station/AP pins 与 live registry，复用原 wake/operation/
   promiscuous/foreign-owner 和 lifecycle identity 耗尽门槛。普通 lifecycle
   入口仍传零 EAP identity，不能借新例外绕过保护。准入不调用 SDK、不提前释放
   helper 或凭据；成功得到的 lifecycle 持续排除新 owner/driver mutation。
3. 中央清理执行器先在该精确 lifecycle 下退休 SDK binding。stale token、
   普通 clear 或已替换的 binding 不得影响当前操作。失败保留 pins 和事务；
   同一 lifecycle 下 SDK 已退休的 clear 是已完成前缀，不再重复 SDK 调用。
4. SDK 借用确认退休后才释放 AP pin，再沿既有 vendor/STOP/AP-netif/Station/
   finish-lifecycle 后缀清理。SDK 与 AP release 都成功才移除该前缀标记：后续
   AP coordinator 已退休、Station netif 或 finish 失败，重试不能重新要求旧
   AP coordinator，也不能再次调用 SDK clear。
5. 整个 stop 完成后才结束配置 control，保留配置自身引用。失败时 status.busy
   继续为 true；wifi status/error 的 cleanup stage/error 报告未完成步骤。
   runtime begin_close 后先接手已有 stop，原 token 可以在 closing 时准确结束，
   随后释放配置。不会在 busy 上永久等待自己创建的 stop 事务。

新的 `s_wifi_eap_stop` 仅保存 control token/binding，不存 JS 指针或额外秘密。
它是一个有界事务记录；不重置身份计数、不复制 profile、不增加配置预算器。

stop 成功后配置保留、SDK Enterprise 关闭。后续 start 或当前 stopped-driver
restart 不自动 enable；再次连接前显式 enable。这个可用序列不作为完整配置
重放或自动恢复政策的替代证明。原有 timeout 等待预算继续适用；SDK 已进入的
同步调用不可抢占，失败/超时可已有副作用，后续 stop 继续剩余清理。

## 构建发现与修复

无 SoftAP/RRM/WNM、但启用 Enterprise 的 C5 Context 首次构建失败：
`wifi_eap_sdk.c` 和 `wifi_eap_install.c` 无法找到 `utils/eloop.h`。
原因是 framework 私有 supplicant include 路径只受 RRM/WNM gate 控制；
Enterprise 本身也直接使用该调度头。已把 Enterprise 加入同一条件。
原始失败日志保留在 `build/w08-eap-stop-noap-missing-eloop.txt`。
共享 ESP-IDF 源码没有修改，SDK 修补仍在各 build directory 内生成。
