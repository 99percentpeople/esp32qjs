# W-02：SoftAP 参数与启动前读回

基线 firmware `d7db8d1`，固定 SDK
`fff9895c82d744c7237be8847347bdd1b07c6643`。本批扩展已有独占 2.4 GHz AP；
不是 APSTA/5 GHz AP、完整 driver config 或 Wi-Fi 功能整体验收完成。

## 原生与公开契约

新增共享 `esp32_mquickjs_wifi_parse_ap_config()`，以及无 driver side effect 的
`esp32_mquickjs_wifi_radio_validate_ap_config()`。解析完 JS 参数后先验证，
Radio start_ap 在申请/改变 driver 前再次调用同一 validator。既有精确 AP lease、
排他 start/stop 和 netif 清理后缀保持；配置/parser 供后续 configure 复用。

| 参数 | 原生字段与实际范围 | 联动/编译条件 |
| --- | --- | --- |
| authMode | open/wpa/wpa2/wpa-wpa2/wpa3/wpa2-wpa3/owe；混合模式正式拼写带 `/` | SAE + SoftAP SAE / OWE SoftAP gates；不加入 WEP/WAPI AP |
| password | open/OWE 无密码，纯 WPA3 1–63，其余密码模式 8–63 UTF-8 bytes | 无 NUL，不能返回/记录；SDK 最终认证验收仍待执行 |
| beaconIntervalMs | 向上取整到 100 TU，最大 60000 TU；默认 100 TU | 1 TU = 1.024 ms，100 ms 请求实际 102.4 ms；有限正数最大 61440 ms |
| dtimPeriod | dtim_period，1–10，默认 1 | 单位 beacon interval |
| csaCount | csa_count，1–255，默认 3 | 通告次数，不承诺客户端收到或已切换 |
| pairwiseCipher | tkip/ccmp/tkip-ccmp/gcmp/gcmp-256；混合正式拼写 tkip/ccmp | GCMP build gate；纯 WPA 必须带 TKIP，SAE/OWE/required PMF 禁止 TKIP |
| pmf | optional/required，RSN 模式适用 | WPA3-only/OWE 要求 required；open/纯 WPA 不接纳该选项 |
| saePwe | hunting-and-pecking/hash-to-element/both | 仅 SAE auth modes，H2E build gate；未指定保持 SDK enum 默认 |
| ftmResponder | ftm_responder boolean，默认 false | FTM enable + responder gate，不注册 FTM initiator/session |
| transitionDisable | transition_disable boolean，默认 false | 仅 WPA3/WPA2-WPA3，不能让 SDK 静默清除此请求 |
| gtkRekeyIntervalSeconds | gtk_rekey_interval，0 或 60–65535，默认 0 | open 不能要求非零 rekey |

SSID、密码、auth、channel、hidden、maxConnections 沿用已存在的参数；channel
仍为 1–11 并核验 driver country，maxConnections 仍为框架上限 4。不因这批
auth/cipher 参数扩展而声明 5 GHz AP、共享 AP 或 APSTA 已经可用。

`capabilities().accessPointOptions` 使用相同 build gate 报告可选值、FTM 与
beacon/DTIM 量化上限。可选值不是可任意组合的笛卡尔积；组合仍受 validator
限制。SoftAP-disabled 返回空 choices 与 false FTM。`features.ftmResponder`
只表示当前 AP option，不代表尚未实现的高级 FTM namespace。

## SDK 证据与未证实点

固定 `esp_wifi_types_generic.h` 明确 beacon 以 TU 计、100 的倍数，以及 DTIM/
CSA/GTK 范围。`esp_hostap.c` 明确纯 WPA+CCMP 会改为 TKIP/CCMP，required PMF+
TKIP 会改为 CCMP，非 SAE mode 会清 transition-disable；框架因此提前拒绝
冲突组合，不把这些请求直接交给 SDK 后仍报告原值。

同一固定版本的 AP authmode 字段注释仍写不支持 OWE，但 Kconfig 有
`ESP_WIFI_ENABLE_WPA3_OWE_SOFTAP`，hostap 的 CONFIG_OWE 路径明确支持 OWE。
本批依据实际 Kconfig/hostap 接入 build gate 并保留原始 driver error，不把旧
注释当作所有 target 的结论；真实 OWE AP 启动/关联仍是集中阶段 not-run，
不能用编译通过消除这项证据缺口。

## 启动、读取与失败

Radio 在 stopped/exclusive AP owner 下写 RAM config，再 get_config，最后
才 start。读取前后的 SSID/密码按逻辑长度比较，不比较无关 padding；auth/cipher
以及请求的 required PMF、SAE PWE、transition-disable、非零 GTK rekey 均验证。
读失败或策略不符记 `ap-config-readback` 原始错误/INVALID_RESPONSE，尚未广播。
AP 错误保留此原生 fault stage，资源交给 stopAP/retirement 的既有清理后缀。

返回的 WiFiAccessPointStatus 从 SDK readback 转换，新增上述非秘密配置字段。
Open 的 cipher/PMF 为 null，纯 WPA 的 PMF 为 null；非 SAE/未指定 PWE 为 null。
没有把配置回读值冒充客户端协商值或 RF 验证结果；完整 AP status 的 MAC/clientCount
等仍待后续查询实现。start 已接受之后，JS 返回对象 OOM 仍需调用者查看状态/stopAP。

临时 JS 解析 buffer、调用者 config 和新增 readback config 都使用已有 secure-zero；
不创建新长期 heap/pool。读取副本是有界栈变量，具体峰值和 internal/PSRAM 静止
比较留待集中阶段，不能仅凭此源码说明宣称 SRAM/heap 验收通过。

## 验证与阶段用例

本批只执行必要 immutable C5 Context 编译、MQuickJS syntax、manifest/feature
文档和 recorded SDK map 一致性检查。首轮编译发现 JS_IsNumber 的 ctx 参数缺失，
已修复后重新构建；最终日志与 hash 见 `build/w02-ap-options-evidence.json`。
未执行全套 Host/Python、其他 target/gate 矩阵、实机或 soak，未提交/刷写/改 workspace。

Wi-Fi APIs 完成后以下生产路径集中验收，当前均 not-run：

- auth/password/cipher/PMF/PWE/transition/GTK 的有效与冲突矩阵；禁用 SAE/H2E/
  OWE/GCMP/FTM、SoftAP-disabled；构造前拒绝与 native validator 二次防护。
- Beacon 的 100 ms→102.4 ms、100 TU 边界、最大值、NaN/Infinity/非数字/溢出，
  DTIM/CSA/GTK 整数上下界；SDK 读回与返回单位一致。
- 第 N 次 JS/native 分配失败、移动 GC、秘密清零；get_config 失败与每个安全策略
  不一致时不得 start；cleanup suffix 重试、Radio owner/lease 不受观察队列影响。
- C3/S3/C5 与 feature-disabled matrix；真实 AP Beacon、DTIM、CSA、认证/cipher/
  PMF/SAE/OWE/GTK/FTM 对端测试，没有对端时逐项记录 not-run。

剩余 APSTA/5 GHz、SAE-EXT/兼容模式/BSS idle、完整 AP status 与 configure 继续
保留在总目标中。长时间 soak 等 BLE API 也完成后执行。
