## SDK 审查与字段交付

来源是固定 SDK 的 `components/esp_wifi/include/esp_wifi_he_types.h`。七个 event
结构和 setup config 都是固定大小的标量/数组，无指针和析构义务。显式包含该
公共声明头；converter 不调用 HE/TWT 操作函数，也不依赖新增 driver symbol。
格式可解析不代表目标能产生事件，更不代表 `wifi.twt` 操作 namespace 已实现。

| 事件 | data |
| --- | --- |
| ITWT_SETUP | statusId、失败 reason；成功 configuration 与 targetWakeTime |
| BTWT_SETUP | statusId、仅 TXFAIL 的 reason；成功 configuration 与 targetWakeTime |
| ITWT_TEARDOWN | statusId、flowId |
| BTWT_TEARDOWN | statusId、broadcastId |
| ITWT_PROBE | statusId、失败 reason（成功 null） |
| ITWT_SUSPEND | statusId、flowIdBitmap、八个 actualSuspendTimeMs 槽 |
| TWT_WAKEUP | typeId、flowId |

ITWT_SETUP 公开头文件明确成功值为 1，不是 ESP_OK。失败时不读取协商 config/time，
交付 null。BTWT 仅在 BTWT_SETUP_SUCCESS 复制协商字段，只有 BTWT_SETUP_TXFAIL
读取 tx-failure reason。ITWT probe 的非成功结果保留 SDK failure reason。

成功 config 保留 setup command、trigger、flow type/ID、wake interval exponent/
mantissa 和 minimum duration count。Individual 另含 duration unit ID、twtId 和
SDK timeoutMs。duration unit ID 0=256 us、1=1024 us；Broadcast 是公开头文件的
256 us count。reserved bit 不复制。字段保留 SDK 报告值，不再做一次输入参数
范围收窄或隐式重新配置。

64-bit target_wake_time 用 {low, high} 两个 unsigned 32-bit 数字交付，包含
UINT64_MAX 也不损失位。没有转成不精确 JS number，也没有声称它是 esp_timer/
callback time 或已完成 RF/TSF 时钟映射；原生目标时间的时钟/单位关联仍由后续
TWT/time 契约与 SDK/实机证据补齐。

Suspend 只复制 bitmap 指定的 flow duration，未指定的槽保持 native 0、JS null；
结果数组恒长 8，index 就是 flow ID。保留原始 statusId 和 reported duration，
不把单个值当作协议或操作成功证明。Wakeup/teardown 同样是观察值，不管理
agreement、替代专属 Future 完成或改变共享 Radio owner。

## 存储、清理与构建边界

payload 改为共同 union：原 Station/AP 字段、TWT setup 值、八项 suspend 数组
互斥存储。C5 ELF DWARF 实测 wifi_watch_event_t 仍是 88 bytes，与上批一致；
ingress/subscriber 的条目大小不变。callback 保持无 JS/heap 分配、零等待队列、
现有饱和丢弃计数与原生控制/观察分离。JS config/time/array 都有 movable-GC root，
异常后释放全部临时 roots。没有 raw struct/padding 导出、native pointer 或新清理槽。

Formal WiFiEvent discriminant 和三个完整 event-data 类型已同步，不是未来 TWT
操作 API 的占位类型。raw export 仍不可用，neighbor 变长 converter、其余 W08
功能和完整生命周期继续开放。
