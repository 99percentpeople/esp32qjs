## 有界请求与身份

生产实现为 `components/esp32_mquickjs/internal/esp32_mquickjs_wifi_raw_tx_lane.h`
及 `src/modules/wifi_raw_tx/esp32_mquickjs_wifi_raw_tx_lane.c`（同组件）。boot-owned
单例只有 9 个请求槽，供未来 8 个 Session 和现有 one-shot Future lane 使用。
Session 层仍需保证每个 Session 至多一个请求；helper 不持有 Session 指针或
注册表，不能代替该限制。请求表无 payload、JS root、runtime、callback、allocator
或 SDK 调用；内部临界区只检查最多 9 个请求，task-context 使用。

request 必须收到空 token，成功分配 exact slot/index 与 monotonic identity。
成功代表进入等待队列，不是 RF 准入。只有最早仍存活的请求可 acquire，重复 acquire
同一 grant 幂等。取消等待移除对应 waiter，不允许 withdraw active；release 只对
active exact token 成功。slot 可复用，identity 不复用；旧 token、错误 slot、重复
release 不改变后来请求。UINT32_MAX 可使用一次，此后明确 exhausted，不因
Radio/runtime restart 重置或回绕。满额请求返回 full，调用层可在 deadline 内重试；
公平性针对已准入请求，不承诺表外请求的次序。

这些 identity 只用于框架调度，**不是 SDK completion cookie**，也不同于 queue
admission sequence、broker operation identity 和 Radio generation。SDK 无 cookie
导致的相关性限制仍见 [broker 记录](2026-09-09-w04-raw-tx-broker.md)，没有因为
增加 scheduler token 就宣称能识别任意迟到的相同 metadata 回调。

## one-shot 与退休交接

现有公开 send 的 Future resource lane 仍约束 one-shot；进入实际后台 worker 前，
必须先取得共享 native grant。等待另一 producer 时不调用 Radio acquire/submit；
共享 worker queue 满时保留 grant 并重试，不重复提交 SDK。等待者取消只撤回自己；
已获得 grant、但从未取得 Radio lease 的取消可以立即归还 grant，即使 worker queue
仍满。identity exhausted 形成 `WIFI_RAW_TX_SEND_FAILED`，stage 为
`lane-identity-exhausted`，不无限等待且不调用 Radio。

worker 已获得 Radio lease 后，公开 Future 完成、超时或转换失败的 destructor
把 grant 与 exact lease/native token 一起转移到已有固定退休槽。原始 callback 尚未
可退休时，grant 保留；SDK 调用返回、Future 结束或 timeout 都不能单独归还它。
reaper 顺序为 native retire → Radio release/idle stop → grant release。Radio stop
失败只重试尚未完成后缀，不重复 lease release；此时即使 lease 已释放，也保留
grant 和 stop_pending。意外 grant release 失败保留 `lane-release` 诊断及退休槽，
不能静默放行另一请求。worker、grant 和退休槽均不保存 runtime/JS 指针。

仲裁器 release 本身不校验 native 终止；调用者有责任按上述顺序提供事实边界。
Radio mutation mutex 和 broker 原有检查继续作为 SDK 最终准入约束；未来 Session
必须先取得 grant 再 queue.take，不能先拿走 packet 后把临时 broker busy 当作
该包发送失败。Session 多 owner 生命周期、batch capture、关闭、rate restore 和
显式 fault recovery 尚待接入，没有强制重启共享 Radio。

## 公开诊断

与 `laneIdentityExhausted`，正式类型及 API 文档同步。waiters 只统计已进入原生
仲裁的请求，不包括仍在 Future resource 队列的调用。不同 native 组件逐个快照，
不声称 status 是跨 broker/arbiter/reaper 的原子事务。没有新增公共方法或占位类。
