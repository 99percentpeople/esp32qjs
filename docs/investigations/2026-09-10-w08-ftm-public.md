## 参数、结果与 Future

所有参数捕获完成后才分配 native Future/Session/report、请求 Radio。MAC 使用
精确长度/分隔符解析并拒绝组播/全零/NUL 后缀；channel、frameCount、burst period、
report capacity、timeout 都拒绝非整数/溢出/隐式字符串转换。字段根在 getter 调用
期间保持有效；Session method 在访问 options getter 前保留独立 native reference。

四个 Future driver 分别负责 start、receive、end、close，无共同排他 Future key
阻塞并发 close；SDK 操作由既有单 worker/Radio owner 串行推进。打开成功仅在 JS
对象分配成功后移交 native reference；打开分配失败/超时/取消会 close 并交给
active registry 继续清理。普通 Session methods 只借用额外 native reference。

receive 返回保存的报告，只有正常等待超时返回 null，取消不修改测距。其 deadline
从 Future 被调度时开始，通过生产 poll/finish 完成；没有把 null 放进 core
on_timeout hook，因为该 hook 只支持拒绝，不能返回正常结果。open/end/close 使用
core deadline 及自定义原始错误；end timeout 保留 end intent 和报告，close/open
的 timeout 保留关闭 intent。未调度的方法取消不会启动该操作。

报告是普通 JS 对象，entries 从已退休 Session 逐项复制；timestampPs 为准确的
low/high 32-bit words。失败分配/转换不重读或销毁 native 报告，未关闭时可再次
receive。已有返回的 JS 数据独立于 Session。close/GC 可禁止后续读取，转换过程
发现存储关闭则抛 ReferenceError；持有 Future native reference 防止 UAF。

## SDK 验证前置

新增原生二进制核对确认，固定 C3/C5 的 `ftm_validate_initiator_config` 在读取
burst_period 后与 1 比较，相等进入错误路径；S3 的 l16ui/movi 1/beq 对应同一行为。
SDK 头文件写 0–100，包含这个会被实现拒绝的值。旧 native validator 接受 1，
可能使已准入的 FTM owner 进入未知提交结果的隔离路径。

现在共享 validator 和公开 capture 均拒绝 1（100 ms）：公开只接受 0 或
200–10000 ms、100 ms 的倍数。保留头文件承诺的 frameCount 值，不根据 SDK
未公开范围扩展输入。证据为 `build/w08-ftm-public-{c3,s3,c5}-validate.txt`；这是
真实 SDK object 的失败分支证据，尚未执行回归 fixture 或硬件复现。

## 注册与诊断

只有 Wi-Fi、CONFIG_ESP_WIFI_FTM_ENABLE 和 INITIATOR_SUPPORT 同时开启时，ROM
表与目标绑定才注册 FTM namespace/class；CMake 把相同的两个 SDK gate 传给
框架 ROM 表生成器。FTM disabled 的 class count 维持原值，不加入空方法/类。
`.d.ts` 把 wifi.ftm 标为可选，capabilities.features.ftmInitiator 和 namespaces
反映实际注册；API manifest 是源码可用表，目标可调用性仍须看 live capabilities。

status 分清 opening/active/ending/draining/completed/closing/closed/faulted、
报告状态、原始错误、cleanup 和精确 sequence/generation。global status 可查看
未返回 JS handle 的打开失败；全局 counts/active snapshot 为分别加锁的观察。
`wifi.status().radio.clients.wifiFtm` 在同 gate 下报告 owner 数，已计入 total。

responderConfiguration capability 只指已存在的 AP ftmResponder 配置。
responder offset、缺失/歧义终态的物理恢复、完整 FTM target/role 及 RF 验收仍待
完成。尚未给这些能力增加正式占位方法，也不提升稳定级别。
