# DPP 信道定时器与原生队列隔离

基线 firmware `d7db8d1`、SDK `fff9895c82d744c7237be8847347bdd1b07c6643`。
本批仍是 DPP 内部实现；公开 Radio/Session/Future 尚未接入。

固定 SDK 的 CHM 超时生产者只把 0/1（min/max）送入原生队列，消费者直接结束
当前操作。已入队的旧消息不会被 disarm 撤回；结束回调可以开始新操作，因此
不能用同一标记区分旧操作。该路径由三目标实际 archive/反汇编确认，动态
调度复现继续保留到 Wi-Fi 阶段测试。

生产修复复用 CHM 的两个 esp_timer，每次 arm 分配不回绕的 32-bit 数字身份，
保存单调时钟 deadline。永久 slot 参数的 timer 回调仅作 deadline wake：在新
deadline 前，旧回调不能发布新操作的超时；deadline 后允许唤醒已经到期的新
操作。从发布开始，原生队列携带不可变的 arm identity，消费者再次核对身份和
deadline。min/max 任一完成和原生 record reset 都先撤销两个 arm，再调用原生
结束逻辑，覆盖回调重入、取消和零时长操作。没有逐 arm 创建 timer/heap record。

仅修改 build-local `wl_chm.o` 的 undefined memset 名称，让同一 object 内的
end/reset 路径也经过撤销逻辑；机器指令和 relocation 不变。C3/S3 record 为
24 bytes、timer offset 36/56；C5 为 28 bytes、40/60。补齐原生 archive、OSI
adapter 与 esp_timer 源码 hash gate；DPP 不依赖 IPv4/SmartConfig 才能获得 hook。
C5 继续共用现有 TWT timer dispatcher，其他 timer 保留原路径。

队列投递失败保留到期身份，DPP 已有的原生 poll 可处理该到期操作，不从 timer
任务重 arm 并覆盖较新的 schedule。创建/启动/停止/删除错误保持原值、撤销
超时权限；删除失败的 handle 保存在 SDK allocation 外，后续只重试清理。
identity 耗尽在 chm_start_op 修改 driver 前明确拒绝。失败保持可诊断状态，
没有承诺 runtime restart 恢复；DPP 私有 status 返回共享 CHM 错误、handle/arm
数量和 queue 计数。handle 删除被接受不等于 esp_timer 任务已完成物理堆释放。

本批验证采用 C3 DPP 现有合法 Build Context 的真实编译参数，对四个生产
translation unit 作 `-fsyntax-only`，通过且零警告；三目标实际 native archive
修补/符号与原始 code/relocation 核对通过。四份新增/更新 fixture 仅 AST，未
导入、编译或执行。没有运行 firmware build、链接新 ELF 或刷新镜像；完整
矩阵、运行和实机验收继续后置。证据为 `build/w08-dpp-chm-evidence.json`。

完整 TX buffer 回收仍需单独接入：当前帧身份在状态发布时撤销，只凭 off-channel
record 清零还不能证明 EB 的 recycler 已返回。已核对实际 recycler 与 C5 共用
入口；下一步将这一释放义务接入 TX/关闭，再推进 Radio/helper、公开 Session
与凭据选择连接。其余 Wi-Fi 实现范围和最终实机验收保持原任务，长 soak 后置。
