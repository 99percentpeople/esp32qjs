# DPP ROC 原生完成与关闭

基线 firmware `d7db8d1`、SDK `fff9895c82d744c7237be8847347bdd1b07c6643`。
延续 [DPP 原生结果与关闭](2026-09-11-w08-dpp-native.md)，本批将 ROC 提交、完成、
取消和回收接入生产 SDK；DPP 的 TX、Radio/worker/Session 和公开 API 仍未完成。

## 源码和固定 archive 的依据

原 SDK 将 ROC_DONE 经过默认事件队列、分配副本、eloop 再处理；队列或分配失败
可以丢失控制完成。旧消费者只比较相同的 RX callback context，没有每次监听的
原生操作身份。此为源码审查结果，尚未执行动态故障复现。

固定 C3/S3/C5 `wl_offchan.o:roc_op_end` 支持 request 的原生 `done_cb`：
在 Wi-Fi task 调用 `(context, op_id, status)`，回调返回后清零 28-byte
off-channel record；有 done_cb 时不发布默认 ROC event。C3/C5 的回调点为
`0xd2`，清零调用为 `0xe6`；S3 分别为 `0xe9`、`0x12e`。这是 SDK 原有 ROC
callback，不是已经删除的 DPP 公共 callback 契约。archive 仍由现有构建 hash
gate 固定；请求结构增加 `done_cb` offset 28 的编译断言。
timer 结束路径经 `chm_end_op_timeout` → `ieee80211_timer_process`/`pp_post`
转入原生任务，再由 `chm_end_op_timeout_process` 调用 `chm_end_op`，与显式
取消采用相同的结束 callback。对应原始对象及反汇编沿用 Action SDK 调查记录。

## 已接入的行为

- 提交前分配不回绕的 64-bit 数字身份，并预留 eloop 调度记录；预留失败不调用
  driver。提交期间就允许捕获完成，返回后才核对实际 driver op ID。
- 原生 done_cb 只在短临界区保存首个结果；不分配、不取 API mutex、不操作
  driver、不投队列。外来 context/错误 ID 被忽略，重复完成计数，不覆盖首结果。
- 原生消费者核对数字 ticket 和 SDK generation，等待提交返回及完整物理
  record 清零后才释放记录、设置 ROC 已处理标志并推进下一信道。没有把回调
  已进入当作 native 已退休，也不在 callback 内重入提交。
- 默认事件 handler 及其 heap payload 已删除。8-bit op ID 可以在原生退休后
  正常复用；旧的已取出 eloop 任务仍携带旧 64-bit ticket，不能清理后继监听。
- 取消沿 exact callback/interface/channel/op ID 的现有 ioctl guard 执行；成功
  提交的取消不重复。清零证明不足时保留记录，失败重试只处理未完成后缀。
  SDK 返回提交失败时同样保留物理回收义务。
- 三处 RX 握手切换现在检查停止 ROC 的返回值。取消/退休失败时不会紧接着
  发起新的协议发送；保留原始错误并沿失败路径清理。
- SDK/result 释放和新初始化额外检查 ROC 记录；私有 status 增加数字操作身份、
  原生错误、held/completed、重复与忽略计数，不包含凭据。

## 本批验证

仅执行一次独立 C3 DPP 增量构建，退出码 0、零警告；app 为 2,840,848 bytes。
日志 `build/w08-dpp-roc-c3-build.txt`。生产 `.inc` 进入生成 SDK source、实际
wpa_supplicant archive；ROC submit/done/poll/reap/cancel 已在最终 ELF。
私有 DPP begin/bootstrap/listen/close 仍无公开 Session caller，不以链接 ROC
辅助函数宣称 DPP API 已交付。

C3 编译记录的 ROC 固定状态为 40 B，非回绕计数器 8 B；没有新增帧池或秘密
副本池。其他目标的实际静态布局及设备预热内存比较仍待阶段验证。

新增 `test_dpp_roc_control.py` 直接包含生产 ROC helper，控制 driver、调度和
临界区边界，登记同步完成、物理回收前禁止复用、300 次 8-bit ID 复用、旧
调度任务、取消后缀、提交失败和调度满额。旧异步/结果用例同步当前职责。
五份 DPP fixture 仅 AST，未导入、编译或执行。完整矩阵、动态复现、RTOS、
GC/OOM、RF 和实机为 `not-run`；稳定等级保持不变。

## 继续保留的缺口

TX 默认事件仍缺实际帧身份关联，不能用当前全局 op ID 代替被发送帧的身份。
当前 ROC 消费依靠预留的 10 ms eloop 轮询；固定 SDK 的 eloop timer 向 Wi-Fi
IPC 提交失败时缺少可靠重唤醒，完整原生执行队列饱和恢复仍须结合 retained
worker 处理。此处解决默认观察队列与 ROC 完成的耦合，不宣称整个 DPP 队列
压力、关闭/重开或 RF 行为已通过。
此外，channel-manager 的 timeout 消费者没有每请求 cookie，会结束消费时的
当前 operation；取消/重开附近的旧原生 timer 消息仍须纳入后续调度隔离检查。
本批的数字 ticket 只约束 DPP 自己的异步任务，不替代 SDK 内部 timer 身份。

其后仍需共享 Radio/helper、IPC/worker/runtime、公开 options/Session/Future/
watch、Connector/混合凭据显式选择与连接安全。其余 Wi-Fi 任务范围不缩减；
集中测试在 Wi-Fi API 完成后，长 soak 在 BLE API 完成后。本批未刷写、串口
操作、提交、推送或修改父仓库 gitlink。
