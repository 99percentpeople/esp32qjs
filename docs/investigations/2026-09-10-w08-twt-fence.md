# W-08：TWT timer/native queue 顺序屏障

基线 firmware `d7db8d1`、SDK `fff9895c82d744c7237be8847347bdd1b07c6643`。
接续 [SDK 快照](2026-09-10-w08-twt-sdk.md)，新增 production `wifi_twt_fence.h/.c`。
本 helper 实际调度 ESP_TIMER_TASK marker，确认 marker 自身 callback 退出，
然后调用既有 Wi-Fi native ioctl fence；尚无 TWT owner/公开 API 调用者。

## 证据与实现边界

固定 SDK 的 `esp_timer_stop_blocking()` 实现在返回前等待 callback running
标志清除；使用一个 RTOS tick 的等待预算，实际耗时仍受任务调度影响。marker callback 只写一个
atomic bool，不获取 owner/Radio 锁、不访问 JS/runtime、不递送观察事件。

与既有 FTM timer/native queue 顺序一致，但这里的状态将由可释放 owner 持有，
因此不能仅看到 callback 最后一次 atomic store 就释放/rebind opaque arg。
必须确认该 callback 已经退出。调用不放在临界区，所有 owner 侧入口须串行。

额外检查 `ieee80211_timer.o` 的 `ieee80211_timer_process`：固定 C5 路径分配
8-byte 消息、保存 timer opcode/arg，经 `pp_post` 交给原生任务；失败路径释放
消息并返回失败。原始 object/disassembly 保存在 `build/w08-twt-ieee80211_timer.*`。
这支持 marker 后还需要原生任务顺序点，不能把 timer callback 结束当作全部
原生操作结束。现有 native fence 实现复用，不另建一个任务队列。

## 状态与清理契约

状态为 owner 的零初始化内嵌 native record；包含精确 token（64-bit identity +
generation）、revision、唯一 timer handle、atomic reached、启动/清理错误和
当前 stage。没有全局实例、JS roots 或额外 wrapper allocation。

| 入口/情况 | 行为 |
| --- | --- |
| begin | 绑定非零 token 和未耗尽 revision；create 后只 start 一次，ESP_OK 表示 marker 已安排，不表示完成 |
| create/start 失败 | 保存原始错误和 stage；已创建 timer 仍归本 record，clear 成功前不重开 |
| poll，marker 未执行 | 返回 NOT_FINISHED，不调用 stop/delete/native fence |
| marker 已写 reached，自身尚未退出 | stop_blocking 使用一个 tick 等待预算；失败保留 handle/opaque arg，不进入下一步 |
| timer callback 已退出 | 接纳 timer delete 后才移除 handle，再提交 native queue fence |
| stop/delete/native fence 失败 | 保存清理错误/stage，后续 poll 只重试未完成后缀；不重复成功的 stop/delete |
| poll 完成 | 缓存此 token/revision 的顺序点；不是 TWT SDK quiescent/retired 证明 |
| stale token/generation/revision | 返回 INVALID_STATE，不取消、释放或完成别人的 marker |
| clear | 先禁止 proof delivery，再 stop/delete；失败后只能继续 clear，迟到 callback 的存储仍有效 |
| clear 成功 | 可复用或释放 record，不意味着 marker 曾执行或 Wi-Fi 已排空；后续 begin 使用 fresh reached 和 marker |

清理失败不覆盖原始 create/start error。clear 不调用 Wi-Fi SDK：即使 native
fence 因 Wi-Fi 已关闭而失败，也能独立退休 marker 存储。`esp_timer_delete`
接纳后可能稍后才实际 free SDK 的 timer object；这里证明的是 callback 不会再
引用 owner，不能把 delete 返回当作瞬间 heap 已归还。

## 尚未提供的证明

本 helper 没有调用 `wifi_twt_sdk_retired` / `event_fenced`，也不停止 TWT driver
自己的 timer。后续仍须：

- 独立确认本操作的 SDK timer/TX/协议工作已退出，排除重新调度；
- owner 在 helper 调用后重新核对**当前** lane 的 token/revision；
- 精确 default event-loop fence，及无 cookie teardown/probe/suspend 的退休；
- 有界 owner registry、Radio/Agreement/Future、runtime cleanup 和物理恢复。

空 SDK bitmap/句柄、elapsed timeout、一次 marker 完成均不足以单独释放 TWT
请求。新 helper 是其中的执行顺序部件，不将完整 TWT 的 contract-pending 改为完成。

## 验证

新增 fixture 调用 production begin/poll/clear 与真实 callback，替换的边界仅
为 esp_timer/native ioctl 调度和返回值。覆盖 create/start 失败、callback 早到、
最终 store 与退出之间的窗口、取消/迟到 callback、精确身份/revision、关闭中
禁止完成、stop/delete/native fence 后缀重试、旧 reached 不复用。仅 AST，
未 import、编译或执行；其边界调度不能当作 ESP-IDF/FreeRTOS 实机竞争证明。

C3/S3/C5、C5 Wi-Fi 关闭 immutable Context 构建、对象/archive/ELF gate、
manifest/feature/schema、strict TypeScript、MQuickJS、SDK map 与 whitespace
证据记录于 `build/w08-twt-fence-evidence.json`。新 helper 尚无调用者，因此
最终 ELF 未链接新函数，镜像大小和前轮相同；没有新增静态可写对象。

完整阶段运行及实机测试后置，long soak 待 BLE API 完成；未操作设备、擦除
