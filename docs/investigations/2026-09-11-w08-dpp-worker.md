# DPP 后台命令与 eloop 失败重唤醒

firmware 基线仍为 `d7db8d1`，固定 SDK 为
`fff9895c82d744c7237be8847347bdd1b07c6643`。本批是内部实现，尚无公开
DPP Session/Radio caller；既有 Wi-Fi API 与待验收范围保持原任务范围。

## 调度原因与修复

固定 `port/eloop.c` 的一次性 `eloop_run_timer()` 忽略
`esp_wifi_ipc_internal(&cfg, false)` 的返回错误。该时刻待执行 timeout 仍在
原列表中；如果没有另一次注册/取消/运行来重新 arm，失败的唤醒会使其停留。
这是实际 SDK 源码确认的控制路径，动态复现仍待 Wi-Fi 阶段测试。

新增 build-local `eloop.c` 修补，在投递失败后取得原 eloop mutex，确认仍在
运行且 timeout 列表非空，再用原定时器延迟 10 ms 唤醒。取消/销毁通过同一锁
与状态检查阻止重启；不另建队列、任务、timer 或 operation registry。
重试对象是无数据的 `eloop_run` 唤醒，实际 timeout 仍由原有到期检查和出队逻辑
决定；此修复不重发协议命令。共享修补也适用于 WPS、Enterprise 和 roaming 的
同一个 supplicant eloop。feature-disabled 构建不替换 SDK 源码。

## DPP worker

- 新增按需分配的私有 worker，持有 bootstrap 输入、原生 identity/status、
  URI/单条完整凭据 scratch、IPC 参数与完成收据。输入使用生产 bootstrap
  parser 预验证，验证时不初始化/修改 Wi-Fi，临时私钥存储清零。
- prepare 执行原生 begin/bootstrap；listen 等待 URI 已生成，URI copy/commit
  不影响随后监听准入。所有 native 命令在 Wi-Fi task 执行。
- URI/凭据通过 worker 自有存储交付，成功 copy 后清零 scratch；copy 失败不
  自动 commit，凭据接收不会隐式安装第一条网络配置。
- 已知的未提交 IPC 错误允许关闭未启动的对象；不明交接保留整个 worker，
  status 不读取可能仍由原生任务写入的字段。迟到收据不授权自动重发或释放。
- finish_capture 在终态后关闭 SDK、保留结果；close 再单独释放结果 owner，
  重试只继续未完成后缀，最后清零 worker。初始化部分成功后失败也走相同关闭
  路径。此处使用已实现的原生关闭证明，没有把它提升为全部 driver TX buffer
  的退休证明。
