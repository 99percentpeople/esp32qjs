# W-08 WPS 原生结果释放与 retained worker

接续[分步停止](2026-09-11-w08-wps-cleanup.md)，本批实现内部 worker、定时器/
Wi-Fi task 顺序及原生结果释放。Radio/Station helper、boot event 排空、公开
Session/Future/watch 仍待接入，不宣称公开 WPS close/reopen 已交付。

## 扫描与回调排空

固定 C3/S3/C5 原始 `libnet80211.a` 均已逐目标提取 `ieee80211_scan.o` 和
`wl_chm.o`，只读反汇编保存在 `build/w08-wps-scan-review/`。核对结果：

- `scan_cancel` 清除扫描标志，调用 `chm_cancel_op`，撤销两个 legacy timer。
- `chm_cancel_op` 撤销 channel-manager timer，同步调用 `chm_end_op`；后者
  先清除当前操作，再调用保存的完成 callback。取消路径还处理 pending callback。
- `scan_done` 先保存 callback，再将 `g_scan + 60` 的 callback 指针清零，
  最后同步调用保存的 callback；标志位在 offset 70/71。三个目标布局一致。
- 这些调用不能单独证明旧 timer 已排队的工作退出。legacy timer 使用
  ESP_TIMER_TASK。worker 停止输入后安排同任务 marker，确认 callback 退出并
  删除 marker timer，随后才 dispatch Wi-Fi task 上的退休/checkpoint。

新的 read-only scan snapshot 拒绝 callback 未清空、扫描状态未静止或缺失
driver 状态；不修改 driver 私有字段。begin 同样拒绝现存扫描，未取得自身
owner 前不替外部扫描执行停止。固定 archive、legacy timer 和 IPC 相关源码
均由构建 hash gate 固定；其他 SDK/target 不能沿用未经审核的偏移。

真实 SDK callback 增加不回绕 revision。checkpoint 记录精确 identity 的
revision；release 再次检查 SDK 状态、扫描静止、未交付 PIN/凭据及 revision。
期间有回调到达时拒绝释放，worker 重做排空。原生 record 释放采用 secure
clear-free，旧 identity 不复用；这不代替外层 Radio 事件和连接 owner 的交接。

## Worker 的存储与失败规则

create 仅校验/复制 SDK config：设备字符串必须终止，PIN 除缺省生成语义外
必须是带 checksum 的八位数字。PBC 接受 SDK 默认配置中的零 PIN，不提供
无关的自定义 PIN。begin/start 在同一原生 dispatch 执行，config 随后清零。

config、IPC 参数、command receipt、status、PIN/credential 输出均放在 retained
worker 中。复制成功后才写到调用方输出，原件由独立 commit 消费；临时结果
清零。finish_capture 保留原生结果，close 则明确清零结果后释放。Future 的
超时/取消不能隐式释放该 worker，外层必须完成 close 后再 release。

已确认的 pre-handoff 错误允许关闭无 native identity 的对象。没有执行 receipt
的其他返回值会保持 `handoff_unknown`，禁止重试、清零和释放，即使后来收到
receipt 也不自动恢复。该状态只读 worker 自己的诊断字段，不读取 native task
可能仍在写的 identity/status/result；不将设备重启说成 runtime restart 恢复。

marker create/start/stop/delete、native stop/retire/release 的失败都保留存储和
当前步骤；多次 close 不重复已成功的停止/删除。任何 native dispatch 中的
未知交接都保留参数存储。当前 worker 尚无公开 caller，外层独占 Radio/连接
准入必须在接入时落实，不能仅凭头文件注释视为已实现。

## 验证与剩余项

新增 `test_wifi_wps_worker.py` 使用生产 worker，控制 SDK/IPC/timer 边界，
覆盖顺序、分步失败、copy/commit、未知交接与迟到执行；原生 fixture 补充
scan snapshot、revision 失效和实际 result release。按安排仅 AST 检查，
没有导入、编译或执行 fixture，也没有 RF/实机运行结论。

本批生产构建、archive/ELF、DWARF 与静态检查证据记录在
`build/w08-wps-worker-evidence.json`。尚须完成初始化/启动/扫描的完整错误
交付、真实 RF 关联/安全检查、Radio 与 Station 配置恢复/事件排空、公开
选项/Session/Future/GC/watch、AP registrar 能力契约及集中运行/硬件验收。
其他 Wi-Fi 剩余范围保持不变，长 soak 仍留到 BLE API 完成之后。

最终 C3、S3、C5 roaming、C5 no-SoftAP、C5 Wi-Fi-disabled 五配置生产构建
通过。三个生成 SDK 源文件与生产 patcher 相符，对应 object 与实际 SDK
archive member 字节一致；worker 同样进入四种启用配置的生产 archive。
最终 ELF 仍无 WPS caller。manifest 54 classes / 530 functions、类型、文档、
schema、SDK coverage 与 MQuickJS 61 源文件/62 片段静态检查通过。

四种启用配置 DWARF 均确认 worker 624 B、worker status 64 B、原生 record
392 B（revision 增加 8 B）、原生 status 40 B、三组凭据 332 B。worker 和
record 按需分配；内部 reserved_bytes 仅统计桥接对象，不包括 SDK 协商堆
和 timer 驱动对象，不能作为完整 WPS 内存峰值。五镜像大小与上一批相同，
disabled hash 不变，C5 roaming 仍余 19,312 B；公开接入后的 SDK 链接空间
需要另外验算，不能沿用当前无 caller 的镜像尺寸作交付容量保证。
