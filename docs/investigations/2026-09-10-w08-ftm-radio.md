# W-08 FTM 原生 Radio 会话与报告退休

本批把 FTM 连接到生产 Radio：内部 start/end/status/snapshot/collect/retire，
尚未注册 `wifi.ftm` 或正式 Session/Future 类型。firmware HEAD `d7db8d1`，
SDK `fff9895c82d744c7237be8847347bdd1b07c6643`；承接
[报告 NULL 释放修复](2026-09-10-w08-ftm-sdk-report.md)。不是 FTM 功能完成或 RF 验收。

## 当前实现

- 已启动的 Station 接口准入；不隐式 init/start/改变 mode。检查实际 mode、法规
  channel、已有 fixed-channel/raw-TX owner、借用配置与生命周期排他。
  同主信道可使用已关联 Station/APSTA；离开主信道只允许未连接 Station 且无其他
  依赖 RF 信道的 owner。不因为 SDK 提供离信道 ASAP 就默认移动现有 AP/连接。
- 精确 token 复用 Radio 的 boot 不回绕 operation identity；独立 FTM lease 和固定
  信道保留。generic end_operation/release 不能绕过退休；身份耗尽失败。
- 单一 boot-owned 配置副本，直到退休才清零。SDK 失败后仍返回已准入 token，保存
  原始 submit_error；不重试 initiation，不假设提交错误必然没有原生工作。
- 默认 event-loop 的 Radio listener 直接记录终态、peer/status/初始化过的摘要；
  不经过 JS 观察队列。早于 SDK 返回的事件可记录。第二条、异 peer 或非法状态
  的报告一律隔离，任何报告都会使先前 revision 排空证明失效。计数不回绕。
- end 只重试失败的 SDK 后缀；成功 end 不等于终态，不释放 owner。终态出现后不
  再发送 end；原始 end_error 仍可在内部状态读取。
- collect 不分配、不保存调用者指针。接收精确 native span，capacity 1..64，
  NULL/0 显式丢弃。SDK 源项数仍保留，复制数量单独记录，可诊断截断。
  64 位 t1/t2/t3/t4 原样保留；尚未做 JS 数字转换。
- 报告复制/丢弃是一次性步骤。成功后不能重复取报告；失败保留清理责任，支持
  后缀重试/丢弃。SDK 返回期间 revision 变化则清空调用方输出并隔离，不能把
  不确定归属的数据交付下一会话。global watch 继续只观察摘要。

## timer、SDK 与事件三层屏障

固定 C5 SDK 二进制 end/abort 路径先 disarm/done 两个 timer，再发布报告，随后
释放 initiator context。`esp_coex_common_timer_*_wrapper` 调用的
`esp_timer/src/ets_timer_legacy.c` 创建的是 `ESP_TIMER_TASK` timer。
`ets_timer_done()` 仅调用异步 `esp_timer_delete()` 并清空 legacy handle，不能
证明已经进入的 timer callback 结束。单独使用报告事件和 native ioctl fence 不够。

现在 collect 首先安排一个同 TASK 的一次性 marker。SDK timer 回调和该 marker
由同一个 timer task 串行执行；marker 到达后，之前正在执行的 callback 已返回。
再调用已有的 reviewed native ioctl quiescence probe，排空这些 callback 已提交
的原生工作，同时确认共享 off-channel record 全为零。每步仍核对报告 revision。
SDK get_report 随后复制/释放报告。retire 最后发布携带精确 token/revision 的
默认事件循环 marker，见证后才能释放 Radio operation/lease。

marker 的 timer 懒创建且 boot 有界复用一份，回调只写 boot-owned atomic flag；
没有 JS/runtime/session 指针。失败创建/启动可重试，不释放 FTM owner。一个
pending marker 被消费后才可重用；旧 token/revision 的完成不证明新报告退休。
这一个 timer 的 SDK heap 分配需要纳入后续 W-09 预算与预热内存基线。

控制 marker 入队失败时保留已经完成的报告领取步骤；重试仅发布未完成的 marker。
事件缺失、冲突、未知 submit 结果目前仍保持隔离；没有把 runtime restart 当作
原生终止证明。独立物理恢复协调器仍待接入。真实 timer/SDK/事件竞争未执行测试。

## 构建及尚缺证据

使用既有不可变 `build/wireless-contexts/c5-ftm` 和独立
`build/wireless-c5-ftm`；生产构建 exit 0，最终日志
`build/w08-ftm-radio-c5-build-count.txt`。FTM disabled 的普通 C5 同步检查，日志
`build/w08-ftm-radio-disabled-c5-build-final.txt`。不执行 C3/S3/feature matrix 阶段测试。

FTM-enabled binary 为 2,852,016 bytes，上一相同 context 为 2,851,504 bytes。
新增 FTM event handler 已链接；start/end/collect/retire 等函数在生产 Radio object
中已编译，但没有公开消费者，最终 ELF 将它们裁剪。getter 也仍未链接；不得把
当前 binary 尺寸当作未来完整 FTM 模块成本。FTM enabled 的 `s_radio` 从 832 增至 840 bytes（一个
4-byte client counter 加对齐），`s_ftm` 为 100 bytes；timer marker 的
20-byte static 和相关路径目前
被 GC 裁剪。FTM disabled 不增加该 counter、静态 FTM 状态或 timer。

`test_wifi_ftm_radio.py` 调用实际生产 Radio 函数与 registry，准备精确 owner、
身份耗尽、早到/迟到报告、SDK 错误、end 后缀、详细报告重复读取/截断、timer
创建失败、marker 队列满和报告读取期间竞争。只 AST 解析，未导入/编译/执行。
注入的是 SDK、lock/storage、timer/event 调度边界，不是另写一个测试状态机。

生成物、SDK map、类型/语法检查及 hash 记录见
`build/w08-ftm-radio-evidence.json`。Host/Python/VM fixture、实机/RF、长期 soak
均为 not-run。未刷写、串口操作、提交、推送、更新根仓库 gitlink 或修改共享 SDK。
