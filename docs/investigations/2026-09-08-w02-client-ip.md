# W-02：AP 客户端可选 DHCP IPv4 查询

基线 firmware `d7db8d1`、SDK `fff9895c82d744c7237be8847347bdd1b07c6643`。
`wifi.apClients(options?: WiFiAPClientsOptions)` 在唯一 v1 中增加 includeIp，
默认 false；参数捕获、注册 arity、源类型、manifest 和 API 文档同步。

## 实际契约

- 没有参数、undefined、空对象或 includeIp:false 只查询原有 MAC/AID/RSSI/PHY。
  includeIp:true 在每项附加 ip: string | null。unknown key、NUL 后缀字段、
  非 plain object、非 boolean、多余实参在 native 查询之前拒绝。
- 先走既有 Radio 精确 AP lease/list/AID 快照，然后按每项 MAC 在本 AP netif
  查询 DHCP IPv4。列表、AID 和 DHCP 不是原子快照；IP 可能属于仍保留的租约，
  不证明客户端仍关联、可达或静态地址，也不为 deauthClient 提供身份保证。
- 固定 SDK 的 esp_netif_dhcps_get_clients_by_mac 在 lwIP 任务读取 DHCP pool。
  下层 dhcp_search_ip_on_mac 未找到时不改写 IP 输出；生产 helper 必须先清零
  所有 pair，再复制 MAC。未命中返回 null，不把未初始化栈内容输出为 IP。
- Runtime task 持有 AP helper/netif；查询不调用 JS poller。固定上限的临时 pair
  在 native 栈上，没有新 owner、allocator、pool 或持久内存；实际 stack/heap
  峰值仍待阶段验收。空 AP 不调用 DHCP。查询失败不发布部分数组、不改变关联。
- DHCP-disabled 且 includeIp:true 在 Radio 查询前报 WIFI_AP_FAILED，原始
  ESP_ERR_NOT_SUPPORTED；默认列表仍可查询。native DHCP 错误记录 clients-ip
  和原始 espCode；已有 AP 清理 stage 不覆盖。SoftAP-disabled 仍使用现有
  WIFI_AP_UNSUPPORTED stub。格式化异常/JS OOM 保留原有原生状态。
