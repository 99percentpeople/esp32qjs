## 源码确认的问题

固定 SDK `src/common/rrm.c` 使用 u8 `next_neighbor_rep_token`，发包后递增。
发出 token 255 时，下一值回绕为 0；响应比较中的 `next - 1` 经整数提升成为
-1，导致合法的 255 响应被丢弃。补丁在比较及对应日志中显式转回 u8。
没有改变 SDK 的 token 分配/reset 策略；8-bit token 回绕和连接 reset 后的
RF 迟到包歧义依然存在，不能用 native identity 声称解决空中 replay 隔离。

同一函数在发送后保存 callback/context，但忽略 `eloop_register_timeout` 错误。
定时器分配失败时原实现返回成功，保留没有超时来源的 callback。补丁检查返回值，
失败清除本次 callback/context、释放 request buffer 并返回 `-ENOMEM`。
TX 已经尝试，错误不能被解释为“未发送”；独立 `tx_attempted` 保留此副作用。

上述缺陷由生产源码确认。本批未执行故障注入，尚无运行失败/修复通过结果。
已准备原版与修复版生产函数对照 fixture，按用户要求等待全部 Wi-Fi API 完成后运行。

## 原生边界

`scripts/patch_idf_rrm.py` 校验 rrm.c、esp_common.c、wpa_supplicant_i.h、
eloop.c 四份已审查源码 hash，只生成构建目录下的 rrm.c。CMake 在 WIFI/RRM
gate 内替换 SDK component 的唯一源条目；原 SDK 及其工作区保持不变。
内部 helper 与真实 SDK struct、static timer handler 在同一 translation unit 编译，
框架没有复制私有 struct ABI。SDK 变化需要重新审查，不能静默套用补丁。

- request 沿用 SDK 公共函数的关联 AP、RRM capability 和 SSID 构造检查；在同一
  supplicant 任务返回前，将默认 observer callback 换成本次精确 callback/context。
  已有 callback 或不一致 context 均拒绝覆盖。
- query 区分无 owner、精确 owner、外来 owner 和不一致存储。cancel 只取消
  精确 callback/context 的 timer 和存储；重复 cancel 空闲状态幂等，不碰外来请求。
- 固定 SDK eloop 每次取出一个 timer 后立即调用 handler，不存在分批取出后留在
  任务外的 callback 队列。因此在此任务内取消可排除同时执行的原生 callback。
- SDK 正常响应、timeout、reset 保留原有“调用 callback 后清空 storage”顺序。
  callback 内仍被 SDK 引用，不能释放或重入 blocking dispatch；必须在后续
  query/cancel 确认 ownership 为 0 后才退休 storage。SDK null report 同时用于
  超时和 reset，当前边界不能独自区分两者。实际 SDK timeout 是 1 秒。
- 默认 WIFI_EVENT_STA_NEIGHBOR_REP 发布被单独暴露为内部 helper。未来 control
  callback 必须先记录终态，再尝试发布观察；队列/分配失败不能作为 Future 完成依据。
  此顺序要求尚待 Request 实现落地，不能以本 helper 代替整个控制链证明。

`esp32_mquickjs_wifi_rrm_sdk_command` 通过 SDK 的 blocking eloop dispatcher
串行化 SUBMIT/CANCEL/QUERY。dispatch 成功与原始 SDK code 分开；未进入 handler
保留 `entered=false, ownership=-1`，不是“已退休”。调用者仍须建立 Radio/operation
保护，并提供 boot 内不复用的非零 identity；本批没有实现该分配器或持久 owner。

## 保留工作

Neighbor Report 仍需有界 operation registry、原生报告复制/解析、公共 Request/Future、
Radio 长期保护、超时与 reset 归因、终态/观察排序、关闭和 runtime teardown。
RF token 回绕/reset 歧义需要明确契约及证据，不使用猜测的等待时间证明隔离。
专属 request/watch 继续 contract-pending，不添加正式类型或注册占位。

C3/S3、RRM-only/WNM-only/11r-only/full feature matrix、Host/Python/VM、
实机生命周期/GC/队列/重启/RF 均 not-run。全部 Wi-Fi API 完成后做阶段验收，
长 soak 等 BLE API 完成。未刷写、串口、擦 workspace、提交、推送或构建前端。
