# W-03：RX 订阅接入 Radio 事务

## 实际实现与入口

新增内部 `esp32_mquickjs_wifi_radio_subscribe_promiscuous()`。它复用 Radio 的精确
lease 和 acquisition identity，串行化 registry 预留、需求合并、driver 配置与
订阅激活。现有 CSI enable-only acquire/release 也使用同一个需求计算入口，
不会因为 CSI 加入或退出而覆盖其他 RX subscriber 的配置。

这是 Monitor 所需的原生入口。尚未新增公开 JS Monitor 方法、Frame/Batch/Source
或采集 pool。新入口已编译到 Radio object；因目前没有生产 Monitor 调用者，
这个入口本身尚未进入最终 ELF。共用 acquire/demand/registry 实现已进入现有
CSI 的 firmware 链接路径，不能把这些事实写成设备已开始捕获原始包。

## 启用与失败

1. 验证 Radio lease、启动状态、生命周期/故障 gate 和 bounded filter。
2. 预留 registry slot，关联到该 Radio lease；此时 callback 不能进入新订阅。
3. 在同一 Radio mutation mutex 下取得所有非 closing owner 的 RX token 集合。
   `owned_requirements()` 在 registry critical section 中逐一核对精确 identity、
   phase、重复项及完整集合；不是仅比较订阅数量。
4. 将共同 packet type/subtype/error-frame 需求转换成固定 SDK masks，提交前批
   driver 事务。只有提交和读回成功后才 activate 新订阅。

失败且回滚完成时移除从未激活的预留 slot；回滚未完成时保持 acquired token、
closing registry slot 和调用方控制存储，并分别记录原始错误与 cleanup 后缀。
激活/registry invariant 错误分别使用 `promiscuous-activate`、
`promiscuous-registry` 阶段，已同步正式 v1 error-stage 类型。

调用方从 reserve 成功到 acquired=false 之间必须持有稳定 native subscriber/
context 存储。未来 Monitor 必须走这个 Radio 入口，不能绕过它直接 activate
registry，然后假定自己拥有 driver mutation 权。

## 需求合并与既有 owner

普通类型显式转换为 SDK MGMT/CTRL/DATA/MISC mask；validOnly=false 的有效请求
增加 FCSFAIL。SDK 仅为 Control subtype 7–15 命名单独 mask。涉及其他 subtype
时请求 SDK 支持的全部 Control，再由已有 native filter 执行精确 predicate。
这不会让 SDK 产生本身无法交付的帧，也不是这些 subtype 的 RF 支持证明。

存在 CSI 等 enable-only owner 时，driver 将首次 claim 保存的原始 packet/control
filter 与 RX 需求做并集。最后一个 enable-only owner 退出后，只保留仍活动 RX
的需求；最后一个 RX 退出但 CSI 仍在时，注销 raw callback、恢复原始 filters，
保持 promiscuous enabled。全部非 closing owner 退出后才 disable 并恢复 baseline。

driver 硬件 filter 允许是软件需求的超集，实际交付以每个 subscriber 的有界 native
filter 为准。原始配置来自 getter，不把默认值当 snapshot。driver setter 仍只有
`wifi_promiscuous_driver.c` 一处写入；没有新会话直接触碰这些 SDK 设置。

## 关闭与排空

release 先将 owner/registry 标记 closing，停止新准入并从需求并集中移除；完成
driver 缩减/恢复后，再尝试 registry finish_close。若已有 dispatch retain，保持
acquired=true 并返回，释放 Radio mutex，不在 mutex 内循环等待 callback。

正常 drain 不会单独写入 Radio fault。控制方重试时，不重复已经完成的 SDK 写入；
只在剩余需求确有变化时更新配置，之后检查 drain。已进入的 sink 仍可完成，控制
存储不能提前释放；完整 Radio release 同样会保留该 Radio lease。旧复制 token
不能关闭同一个 Radio lease 后续重新申请的 RX identity。

原生 SDK 调用本身可能等待 driver task，此入口不承诺可抢占 SDK 的硬时限。
sink 必须遵守无 JS/Radio/SDK 调用、无等待与有界复制契约；测试中的暂停只用来
控制调度，不是生产允许的行为。callback 只取 registry lock，锁顺序不允许反向
从 sink 进入 Radio mutation。

## 已补测试源码，未运行

Host C Radio fixture 现在调用实际 Radio、driver 事务、registry、MAC parser 与
native filter。SDK callback span adapter 是该集成 fixture 的明确边界替身；真实
legacy/HE layout 由既有 recorded-SDK Python fixture 单独覆盖，不将二者当作
真实 SDK/硬件时序证明。

新增 Radio cases：

- `promiscuous-rx-union`：setter 内同步 callback；新订阅在 commit 前不接收；两个
  RX 与 enable-only owner 的需求合并、恢复、旧 token 和最后 callback 注销。
- `promiscuous-rx-drain`：暂停已进入的 sink；close/full Radio release 返回并保留
  引用；查询仍能获取 Radio mutex；重试不重复配置写入，另一个 subscriber 继续。
- `promiscuous-rx-failure`：更新/回滚失败、新订阅不提前激活、原订阅仍接收、关闭
  注销失败后停止准入并保留控制，重试完成原生后缀。
- `promiscuous-rx-capacity`：8 个 subscriber 上限，第 9 个失败不触发 driver。

registry Python fixture 新增完整 token 集合、缺项、重复、同数量错误 identity 和
closing 排除；driver fixture 新增 SDK mask 转换、保留/移除 enable-only baseline。
所有这些测试源码均未编译或执行，只执行修改的两份 Python AST 检查。
