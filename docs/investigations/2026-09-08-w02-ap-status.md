# W-02：AP 当前状态与读取失败诊断

## 已编码契约

`wifi.status().accessPoint` 已进入唯一 v1 的源类型和公开状态转换；没有 live/pending
AP helper 资源，或未编译 SoftAP 时返回 null。它不隐式初始化/启动 Wi-Fi。
存在 AP 资源时包含：

- `started`：Radio 最近收到的 AP_START/AP_STOP 状态。不是 DHCP、IP 或客户端就绪。
- `cleanupPending` / `cleanupStage`：AP helper 当前关闭义务与阶段；保留原有诊断。
- `queryError` / `queryStage`：本次读取的原始 SDK 错误和阶段，不回写长期 cleanup 状态。
- `ssid` / `ssidBytes`：UTF-8 文本与精确原始字节；非法 UTF-8（包括孤立 surrogate）
  文本为 null，bytes 仍可用。二进制 SSID 内的零字节不被截断。
- `hidden` / `authMode` / `maxConnections`：当前 SDK AP 配置的非秘密白名单字段。
- `channel`：SDK 当前物理信道，不重放配置中的请求信道；APSTA 可能跟随 Station。
- `clientCount`：SDK 当次关联列表数量，区别于 Radio owner/lease 计数。
- `mac`：当前 AP interface MAC。

原生采样失败时，started 和清理诊断仍保留；全部采样字段为 null，并给出本次错误。
查询中的配置、MAC、client count、channel 是相邻的独立观察，不构成原子 RF 快照。
查询失败不使整个 wifi.status 抛出；JS 结果分配失败仍按常规抛出异常。

## 生产读取与秘密边界

`esp32_mquickjs_wifi_radio_sample_ap` 使用实际 lease registry 校验精确 identity、
generation 和 AP role。持 Radio operation mutex 完成 getter，排除框架 driver
mutation/deinit；SDK 调用不放在短临界区里。生命周期过渡、fault/cleanup 或没有
健康 AP lease 时拒绝 SDK 读取。关闭中的 helper 传 NULL lease，仅观察 AP 事件
状态和返回 admission 失败，不从已退休/正在退休的 driver/netif 读配置。

mode → 临时分配 → get_config → MAC → client list → actual channel；结果只复制
白名单字段。完整 wifi_config_t（含 password）与 station list 使用同一个临时
heap allocation，不增加 boot pool 或 runtime 大栈缓冲。所有成功、getter 失败、
长度/计数错误和最终 AP_STOP 检查的出口都用已有 secure-zero 清空整个 allocation
后释放，再进入 JS 分配。失败清除已部分采样的 public fields，避免混合有效/旧值。

SSID 的长度上限为 32，长度 0 使用 SDK 的 NUL-terminated fallback 约定；native
client count 在复制前检查 SDK 上限。MQuickJS `JS_NewStringLen` 明确要求有效
WTF-8，不能直接接收任意 SDK SSID；新转换复用 vendored cutils 的有界 UTF-8
解码先验证，再创建文本。实际源码依据为 vendor/mquickjs/mquickjs.c 的
JS_NewStringLen 前置条件及 cutils.c 的 unicode_from_utf8。bytes 数组和父结果
使用独立 GC roots，无 native buffer/lease/JS pointer 从查询逃逸。
