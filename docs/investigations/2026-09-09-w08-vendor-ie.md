# W-08 Vendor IE 配置接口

基线 firmware `d7db8d1` 工作区增量，SDK `fff9895c82d744c7237be8847347bdd1b07c6643`。
本批注册唯一 v1 的 `wifi.vendorIe.set/clear/status`，保持 Candidate。

## 契约和实现

SDK header 明确 set 返回后输入无需保留；每帧两个槽，重复 set 必须先 clear。
已提取 C3/S3/C5 的 public wrapper 和 wifi_set_vnd_ie_process：wrapper 用 24-byte
id 29 消息提交 enable/frame/index/input；writer 校验 frame 0..4、index 0..1、
0xdd 和最小 length 4，分配槽对象与 length+2 字节副本。删除释放副本和槽对象。
beacon 改动还设置重建标志。因此本批不将它列为 STOP-neutral writer。
固定库、object 和反汇编在 `build/w08-vendor-ie-sdk/`；静态审查不是 RF 证明。

正式选项为严格 interface/frame/index/enabled/data。Station 只允许 probe-request
和 association-request；AP 允许 beacon/probe-response/association-response。完整
单 IE 长度 6..257 且 length+2 严格相等。字节在 JS getter/GC 后通过 root 取值，
ByteView 读取使用 lease 并立即复制；全部预验证后才进入 Radio mutex。

Radio 记录最多 10 槽，每接口一份真实 registry lease，成功和不确定槽都阻止物理
关闭/重配置。没有常驻 IE 副本、JS root 或 callback 指针。SDK copy 上界通过
status 报告（不包括 allocator/SDK metadata）。重复启用拒绝，不自动清除或覆盖。
SDK 返回错误后保留 uncertain；明确 clear 逐槽执行，成功立即退休，失败保留。
再次 clear 只尝试尚未完成的槽，最后一个槽退休才释放该接口 lease。其他 Radio
fault 不被清除。runtime teardown 接入 clear，失败记录 vendor-ie-clear，后续
runtime 初始化继续原清理。新增 client 计数进入 wifi.status().radio.clients。

当前要求 STARTED：已有 STOPPED → start 的独占配置交接尚未接受这些持久 owner，
不能将“setter 在 SDK 可调用”误称为预启动生命周期可用。预启动交接仍留在 W-08。
watch 接收侧有界 callback 队列也未实现，不注册占位方法。当前 features.vendorIe
和 namespaces 仅报告这三个已注册配置方法。
