## 已接入的生产路径

原 SDK 将 TX 状态先发布到默认事件队列，再分配副本并排入 eloop；协议端只按
8-bit operation ID 匹配。静态检查还确认，duration/cancel 状态也会清除
`pending_tx_op_in_progress`，使随后发送结果失去消费者。运行复现留到 Wi-Fi
阶段测试；这里的缺陷依据是固定 SDK 源码和实际 archive 调用链。

- 先前加入的实际帧身份过滤，保留 EB、原生 context/interface/channel/id，
  在原生 record reset 和 recycler 前撤销；非对应发送帧不能产生当前操作的
  TX DONE/FAILED。该绑定只标识发送帧，不拥有或释放 SDK buffer。
- 本批在 `wl_offchan.o` 的 `wifi_event_post` 调用边界捕获 DPP TX 状态。
  发送结果与 dwell 结束分别保存在一个有界原生记录中，捕获不分配、不获取
  DPP API mutex、不调用协议逻辑。DPP TX/ROC 观察采用零等待发布，其他 owner
  保留原有发布路径。
- 提交前保留调度入口，并分配不可回绕复用的 64-bit ticket；同步完成可以先于
  driver 返回，返回后再核对原生 ID。eloop 仅携带数字身份；移除默认 TX 事件
  消费者和完成事件堆副本，避免排队的旧状态按新的 8-bit ID 命中新操作。
- TX DONE/FAILED 只交给协议一次；duration/cancel 不消费发送结果。协议推进
  需要新 TX 时先取消并退休原操作。已成功取消但尚未清空原生记录时保留占用，
  关闭重试只处理未完成后缀。缺失发送结果不被当作发送成功。
- 发送请求临时存储释放时清零；private result status 增加 TX ticket、错误、
  完成/占用和忽略/重复计数，未新增公开类型或 placeholder API。

## 验证与剩余范围

实际 C3/S3/C5 SDK archive 已分别通过固定 hash gate 并执行生成；这不是三个
应用构建。一次受影响 C3 DPP 增量构建通过，零警告，镜像 2,843,664 bytes。
ELF 确认原生 publisher → 捕获桥接，以及 TX 提交/取消/poll/协议处理均已链接；
TX 状态记录为 48 bytes，独立不可复用计数器为 8 bytes。日志为
`build/w08-dpp-tx-c3-build.txt`，43 个文件的产物核对/hash 记录为
`build/w08-dpp-tx-evidence.json`；共享 SDK 保持干净，公开类型/manifest 未变。

顺序、重复/错误身份、旧数字调度、队列失败、提交失败、取消后缀和身份耗尽用例。
