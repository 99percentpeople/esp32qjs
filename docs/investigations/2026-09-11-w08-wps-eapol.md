# W-08 AP WPS EAPOL 定时器与客户端处理边界

基线 firmware `d7db8d1`、ESP-IDF
`fff9895c82d744c7237be8847347bdd1b07c6643`。本批继续补 AP registrar 的
内部生命周期，不新增公开 API，不将 Candidate 提升为稳定。

## 固定 SDK 路径

`eapol_port_timers_tick` 和 `eapol_sm_step_cb` 原先把 EAPOL 指针放入 eloop
参数。`eapol_auth_free` 取消 timer 后直接释放；已经派发的回调不因取消而自动
失效。`AUTH_PAE/ABORTING` 还排队执行无 cookie 的全局 AP WPS disable，不能
区分发起 abort 的客户端或 WPS 操作。

客户端不能按单 Wi-Fi task 假设处理：`esp_wpa3.c` 的 SAE task 也会删除
`sta_info`。SDK 对应路径持有 `sta->lock`，从客户端表摘除后再释放 EAPOL；
而 `ap_get_sta()` 返回的指针在解锁后没有存活保证。本批将相关 SDK 源码与
头文件加入固定 hash 核对，保留既有 semaphore/客户端表锁语义。

这是源码路径核对，尚未执行调度/竞争注入。

## 已编码的生产路径

- EAPOL allocation 在原 SDK state 之后附加 AP identity、两个 timer ticket、
  原始错误与 stopped 标志；一次分配，不修改其他 translation unit 使用的
  SDK struct 定义。
- timer 参数只含 AP identity 与 boot 内不复用的 32-bit pending-operation
  number。号码耗尽返回错误，不回绕；runtime restart 不重置。消费、取消及
  peer free 均撤销 ticket。连续 step 请求合并到已有待执行 step。
- callback 先取得精确 AP activity 引用，在真实客户端表内查找对应 EAPOL，
  并在释放表锁前取得 SAE peer semaphore。随后运行原生产 EAPOL handler；
  结束后释放 semaphore，或按 SDK 约定处理已标记的客户端删除。
- SAE peer 忙时用同一未执行操作的数字参数延后 1 ms，不保留 peer 指针。
  若客户端在这期间被删除，重试查找不到该 ticket；重新分配同地址也不会匹配。
  重试注册失败时重新锁定客户端表，仅对仍持有该精确 ticket 的记录停止剩余
  timer，再保存 AP 原生错误；不使用解锁前的 peer 指针，也不修改替代客户端。
- EAPOL receive 同样保护 AP activity 和 peer semaphore。无 registrar 构建
  沿原接收主体继续；未降低认证条件或将 EAP-Failure 解释为成功。
- 首公开终态之后允许原生 EAP 完成剩余协议步骤，但 close intent 之后拒绝
  新 activity。整个 step 和 timer dispatch 都保护父对象，退出始终按精确
  identity 递减。AP 原生删除在 activity 存活时走延迟删除路径。
- timer 注册失败停止本客户端的两个 timer，保留原始错误；初始化遇到该错误
  返回失败并清理本次 EAP allocation。EAP abort 改为本客户端停止和失败记录，
  删除无身份的全局 disable，不直接关闭其他客户端/registrar。
- AP 关闭前缀增加 EAP timer 撤销步骤。它冻结现存 EAP 记录，不释放仍被原生
  代码引用的 heap，也不把“取消数量为零”当作完整输入排空证明。

三目标生产对象 DWARF 显示原 EAPOL state 为 296 B，嵌入的完整 record 为
320 B，每客户端增加 24 B；boot ticket counter 为 4 B。AP result record 的
56 B 大小不变。没有新增固定 peer 池，运行期峰值/碎片与 SRAM 基线仍待实测。

## 验证记录

九配置生产构建、静态契约与对象/ELF 核对通过，记录在
`build/w08-wps-eapol-evidence.json`。普通五配置镜像大小不变；三个 registrar
配置 C3/S3/C5 分别为 2,808,496 / 2,699,648 / 3,194,816 B，相对上批增加
1,968 / 1,904 / 1,984 B。独立 C3 no-SAE 镜像为 2,763,328 B，能力关闭造成的
体积差不作为功能相同状态的优化收益。

首轮 registrar-enabled 编译暴露生成文件的 include 顺序错误：AP header 早于
SDK common 类型定义。调整为在 EAPOL 头文件之后包含 AP header，再构建。
首轮日志保留为 `build/w08-wps-eapol-*-before-include-order-build.txt`。

另从 C3 registrar context 复制独立 no-SAE context，仅修改 context identity/
label 和两个 SAE Kconfig 开关，保留硬件/profile/分区/flash_data。该构建发现 SDK
`ap_free_sta_timeout` 的 `done` 标签在 SAE 分支关闭后未被使用；按相同的
`CONFIG_SAE` 条件包裹标签，不关闭编译告警。该失败日志和补 busy-retry OOM
之前的构建日志保留为 `build/w08-wps-eapol-*-before-busy-error-build.txt`。
未向设备刷入关闭 SAE 的配置。

`test_idf_wps_eapol.py` 使用生产 timer helper 和 peer release，登记旧 ticket、
同地址复用、SAE busy 后删除、回调期间 peer pin、OOM/identity 耗尽、step 合并
和 close 撤销；AP result 用例补终态后的 native activity 与 close 门槛。
按照阶段安排仅做 AST 解析，不导入、编译或执行这些运行用例。

## 未完成的原生退休

`ap_free_sta_timeout`、延迟 EAP-Failure disconnect 和 AP PIN 辅助 timer 仍需
精确客户端/操作身份；不能仅按 MAC 再查找并删除重连后的客户端。WPA3 task 从
客户端表摘除后到 EAP 析构结束之间的存活交接还需纳入关闭账本；本批 timer pin
不代表这段跨任务析构已排空。

仍须完成部分初始化失败保留、queued RX/driver/native 顺序屏障、精确托管
heap/result release、worker/IPC、Radio/AP lease 和公开 AP Session。托管
record 继续禁止从普通 SDK disable 路径释放。竞争/GC/OOM、实机/RF与共存
均 `not-run`；长时间 soak 延至 BLE API 完成后。
