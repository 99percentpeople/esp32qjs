## 当前实现

`wifi.action.remainOnChannel(options)` 已注册 native Future，SDK 接受后返回
`WiFiRocSession`，不把接受请求说成完成驻留。Session 的 `status()` 返回快照；
`wait(options?)` 等原生终态、两级 fence 和 Radio 释放；`close(options?)` 请求取消并
等待同样的排空。后两者也是 native Future。ROC/open/options/status 类型进入唯一 v1，
构造函数只允许工厂创建，无占位方法或旧格式别名。

原生 Session 管理调用真实 Action/ROC Radio owner，不替换原生 lane。Session 建立时
只分配 native storage 和预算，不进行 SDK 操作；所有 JS getters/enum/时间/channel/bool
在开始之前捕获。预启动拒绝和 GC/capture 失败也不会趁机调度新的驻留。

一个 active registry 持有一个 native reference，排队 worker 持有另一个 reference。
Future/JS handle 各自拥有 native reference；worker 不引用 Future state、JS root、runtime
或 task。一个独立锁保护 Session state/引用/预算；SDK、worker 队列和分配调用均在锁外。
工作线程提交后重读 close intent，并在最终发布时合并可能并发到达的关闭请求，避免覆盖
timeout/GC/runtime teardown 的请求。

自然终态自动退休；公开 close、打开失败、打开结果对象 OOM、打开超时、GC 和 runtime
销毁请求关闭。成功 native cancel 只提交一次；失败取消可重试，迟到自然终态仍能继续
退休。原生终态后复用已有 SDK ioctl/default-event-loop 精确 token+revision fences；
队列满保留 owner，成功后释放 Radio。未调用 SDK 的关闭可以直接结束。所有真实请求
使用唯一固定 rx callback identity，done_cb 保持 NULL 以确保原生事件完成路径不被屏蔽。

`wait` timeout/cancel 只结束 waiter；已经开始的 close 在 timeout/cancel 后继续原生清理。
wait 和 close 不共享阻塞 Future resource key，因此 wait 不会阻止 close 开始；单个 native
Session worker 负责 SDK 串行化。queued close 在开始之前被取消，不产生关闭副作用。
打开 Future 完成时驻留可能已经结束；返回的对象可直接是 closed 状态，不能虚构仍在 RF 驻留。

共用 **8 个 native handle** 上限，包括待启动、活动及 JS 仍保留的 closed handles。
显式 close 不绕过预算；最后 reference 释放才归还 budget/storage。公开句柄 GC 后仍有
active/worker reference 可进行关闭。closed JS handle 缓存请求与最终原生快照。

`wifi.action.status()`/`wifi.status().radio.action` 新增 kind、rocHandles/rocActive
以及原生 ROC error/stage/cleanupError/cleanupStage，GC 后仍可检查失败责任。
这些分别受锁保护的 observations 不声称跨所有记录原子一致。
ROC 复用 Action poller，无额外 async poller 或通用容量扩张。
