# W-08：TWT 原生请求记录与退休证明边界

基线 firmware `d7db8d1`、SDK `fff9895c82d744c7237be8847347bdd1b07c6643`。
接续 [输入捕获](2026-09-10-w08-twt-capture.md)，新增生产 `wifi_twt_lane.h/.c`。
本轮是内部请求记录实现，尚未接到 Radio、SDK 调用、事件 broker 或公开 JS API。
不能把本记录的证明消费函数当作已经实现的 SDK 退休探针。

## 身份与状态

- 所有记录必须共用一个 boot identity domain，由 owner 在同一锁下串行访问。
  64-bit identity 递增，耗尽失败；generation 参与精确 token 校验。释放旧 token
  不能清空新记录。domain 不随记录释放、runtime 或 driver restart 重置。
- iTWT connection ID 使用独立 15-bit 单调前缀。显式指定 ID 必须不小于下一
  可用值，跳过的前缀也不再使用；32767 后明确耗尽。预留后即消费 ID，即使
  未提交便关闭也不回收。无需增加 4096-byte 位图。此项为内部准入策略，公开
  options 及 limits 文档仍须在最终 API 接入时展开。
- 原请求、SDK in/out 写回、AP 响应各自保存。SDK 改写 flow 以及 AP 再次改写
  都不会覆盖请求 cookie 或把请求 flow 冒充最终 Agreement ID。
- SDK 调用期间到达的 setup completion 可立即记录；稍后的 SDK 返回保留原始
  error，不覆盖已收到的 AP snapshot。SDK 的 setup success 是 1，零不是成功。
  响应保留完整 64-bit wake time；重复比较逐字段进行，不比较 struct padding。
- 同 cookie 的冲突响应进入 ambiguous；保留第一份响应，不猜测哪份为真。
  bTWT 成功响应还检查实际 ID、command、duration、mantissa、exponent 和 flow
  type。iTWT 请求侧的 100 ms timeout/10 ms sleep 不套用于 AP 响应字段。

## 关闭和清理

| 情况 | 记录行为 | 不能据此推导 |
| --- | --- | --- |
| SDK 提交前关闭 | 禁止提交，可释放该记录 | 已消费的 boot/cookie 身份可重用 |
| 提交期间或等待响应时关闭/公共 timeout | 记录 close intent，保留原生状态 | native 操作、定时器或回调已退出 |
| setup 成功 | 保存 AP Agreement ID，保持记录 | Future 完成即可释放 Agreement |
| teardown 提交失败 | 保存 SDK 原始错误，取得原发送退休与事件排空证明后才允许重试 | 回滚成功或 native 无副作用 |
| teardown callback 早于 SDK 返回且发送失败 | 失败事件优先于 SDK 的 ESP_OK 接纳，重试仍要求两份独立证明 | SDK 接纳等于无线发送成功 |
| teardown 成功事件 | 保存状态，仍保留记录 | native timer/回调均已退休 |
| SDK 退休证明后又有匹配事件 | revision 递增，清除 SDK/event 两份证明 | 旧 event-loop marker 仍有效 |
| revision 耗尽或身份歧义 | 不回绕；无独立证明时保留记录 | 超时可解除隔离 |
| 独立 SDK 退休确认 + 精确 event-loop drain | 允许释放对应记录 | 这些确认已由本 helper 实际执行 |
| 实际 deinit + event drain | owner 可记录物理终止后释放 | 任意 disconnected 标记或 runtime restart 等价于 deinit |

记录不持有 JS roots、不分配内存、不调用 SDK，不受观察 EventQueue 容量影响。
无 cookie 的 teardown 重试有独立发送退休/事件排空标记，不能用“Agreement
仍存在”替代发送退休，也不能用一条失败事件直接释放下一次发送槽。任何匹配
事件都使这两份重试证明失效。独立发送退休探针同样尚待 SDK adapter 实现。
后续 owner 须在其锁内先更新此控制状态，再唤醒 Future 和发布观察事件；SDK
调用必须使用锁外的独立参数副本。当前没有全局 record/domain 实例。

## 仍须接入的原生边界

1. 有界 owner registry、实际 Radio lease/代次/连接/HE/省电准入，以及后台 worker。
2. bTWT setup、所有 teardown、probe/suspend 均有无 cookie 路径；必须先证明
   旧 native 操作和事件退休再复用。外层新 token 不能给无身份事件补造身份。
3. SDK 已建立 flow 位图不能证明 pending setup、timer 或 callback 已排空。
   本轮 `sdk_retired` / `event_fenced` 只是精确证明消费入口，独立 SDK 探针
   和 event-loop marker 尚未实现。既有 63 值 RF dialog token 回绕风险也未消除。
4. Agreement、Future、watch、runtime cleanup、恢复、预算及公共类型/注册。
   suspend/resume 与 bTWT info 布局仍沿用上轮的待核对项。

未增加公开占位方法；完整 TWT 仍为 contract-pending。
