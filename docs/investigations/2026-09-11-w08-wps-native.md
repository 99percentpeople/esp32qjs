# W-08 WPS 原生结果 owner 与定时器身份

在[凭据修复](2026-09-11-w08-wps-credentials.md)基础上，固定 SDK 的 build-local
`esp_wps.c` 现在接入内部 native bridge。此批是公开 WPS Session 的前置实现，
没有公开 JS API，也未完成原生退休、Radio 准入或实机验收。

## 实际行为

- `native_begin` 只在 Wi-Fi task 上执行，检查 SDK init/mode、WPS owner、DPP、
  旧 success timer 和现存结果记录，预留单个堆 record 后才启用 SDK。身份为
  boot 内单调 64-bit 数字，耗尽拒绝，不回绕；enable 失败也返回并保留已取得
  的 identity。SDK config 仅在同步 native enable 内使用，外层 IPC 的存储寿命
  仍须由后续 worker 负责。
- 所有 record 读写限定 Wi-Fi task；跨 task 仅有一个 atomic held 准入提示。
  begin/start/status、PIN 与凭据 copy/commit、close 都使用精确 identity。
  status 只含元数据。单纯复制不消费原件，转换失败可重读；commit 与 close
  使用已有 secure-zero，关闭后不能再读取秘密。
- 原生 PIN 被同步复制进专属 record，不进入默认 event queue。成功时保留
  1–3 组凭据及精确长度、auth/encryption、key index 和 MAC；不依赖 SDK 原
  success event 的“单凭据无 payload”特殊语义，也不保留 parser 借用指针。
- 托管成功不调用 SDK 的自动配置/自动连接分支：保留结果，停止协商，再由
  后续 Station helper 按显式安全策略连接。托管失败也不启用 SDK 的隐式
  reconnect-on-failure。未托管的 SDK 调用保留原来的成功/事件行为。
- 托管 failure/timeout/overlap 先写原生终态和错误，再执行 SDK 停止步骤，
  不调用默认事件队列。上层仍须先完成 Future，再发布脱敏观察；这一层不会
  提前把凭据、PIN 或 Future 终态送进 global watch。
- 十处 timer registration 使用完整 identity 的高/低 32 位作为两个 callback
  参数，没有把 heap pointer 当 cookie。六个 timer handler 检查精确身份及
  closing/terminal 状态；取消按该 WPS handler 的全部 context 排除旧注册。
  timer 注册失败保留原 SDK 返回值，start/status 可见，不在仍使用 state 的
  注册调用中提前释放 SDK 存储。
- 无 cookie 的 scan/RX/start-pending/deauth 回调在托管终态/关闭后停止修改。
  这只解决当前 owner 的撤销，不证明旧回调已经排空或可让下个 owner 复用。
- Public SDK enable/start/disable 在 held 时拒绝。已排队的 enable/start 也在
  native 函数内核对 context；disable 改为在 native callback 准入后修改 type，
  防止 API caller 在排队期间提前撤销新 owner。SDK 自发 disable 记录为托管
  failure。AP registrar 的完整桥接/准入仍待后续实现。
- 显式 close 撤销 PIN/凭据，断连、禁用 type 和 SDK disable 失败保留后缀；
  已成功的步骤不重复执行。`disable_returned` 仅记录 SDK 调用成功返回，绝不
  表示 scan/TX/原生队列已排空。

## 尚未完成的关键边界

目前刻意没有 native record release/reuse 接口。SDK disable 内部仍有忽略返回值
的 driver 清理；scan completion 无 cookie，原生 TX/事件/IPC 也需各自退休证据。
这些必须在后续 worker 中落实，不能只看 `gWpsSm == NULL`、SDK owner=NONE 或
`disable_returned` 就释放 record。当前桥接未链接到公开 caller，不是可重开 WPS
Session 的交付；设备重启也不作为正常 close 的替代实现。

后续还需原生异常关闭与 teardown 检查、精确清理后缀、IPC 参数寿命和未知
handoff、共享 Radio/连接 owner、完整参数/结果契约、PIN/凭据公开转换、GC 与
Future、观察队列、AP registrar 能力契约，以及阶段运行/RF 验收。

定义及已修改的 timeout/event 函数。测试边界注入 SDK allocator/driver/timer，
覆盖 native task 限制、身份高/低位、旧 timer、PIN/copy/commit、三组最大凭据、
清理失败后缀、关闭撤销、timer 错误、enable 失败保留与身份耗尽。case 之间的
fixture disposal 不构成生产 release，也不证明 scan/TX 退休。

提交或推送；长 soak 继续留到 BLE API 完成后。
