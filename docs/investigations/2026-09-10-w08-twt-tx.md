# W-08 TWT 管理帧发送存活观察

基线为 firmware `d7db8d1`、SDK `fff9895c82`，增量保留在 firmware 工作区。
本项已接入生产 C5 发送/回收路径及内部 SDK snapshot；不是公开 TWT API，
也不单独提供 SDK retired 结论。运行与实机用例按用户安排集中后置。

## 确认的原生路径

固定 C5 net80211 的 setup、teardown、information builder 分别设置 EB metadata
offset 20 的 callback bit 19、18、20，然后调用 `ht_action_output(node, eb)`。
metadata 指针在 EB offset 56。后者进入 `ieee80211_mgmt_output`：可直接发送，
也可缓存在离信道链表，或者经原生错误分支回收。因此 output 返回不是发送退休。
普通管理帧 allocator 按长度选择原生 pool type 3/2/4；不改帧内容、PMF 或原生 allocator。

仅看 libpp 的对象反汇编不足以验证最终调用：C5 linker 实际把
`ppProcTxDone`、`ic_ebuf_recycle_tx`、`esf_buf_recycle` 解析到 ROM trampoline。
本机 ROM ELF `20260528` 的 rev0/rev100 均确认：

- `ppProcTxDone` 先经函数表调用完成 callback，然后经 `pp_wdev_funcs + 304`
  调用 recycler；`ic_ebuf_recycle_tx` 也使用该函数表 entry。
- 实际固件 `wdev_funcs_init` 把 `__wrap_esf_buf_recycle` 写到上述 entry。
- wrapper 的 real 调用仍进入 `0x40000bfc` 的原生 recycler trampoline，
  此 trampoline 直接跳原生函数，不重新读函数表，故无 wrapper 递归。
- 三个实际 TWT builder 的最终 ELF 调用均指向 `__wrap_ht_action_output`。

构建继续 gate net80211 全 archive SHA；另增加 libpp 和两份 C5 ROM linker
文件 SHA gate。未修改 SDK、ROM 或 immutable Build Context。ROM ELF 属静态审查
证据，不能代替设备 ROM 身份重查或实际 RF/生命周期测试。

## 实现与资源

`wifi_twt_tx.c` 在 output 前登记精确 EB 地址。独立 slot 一直保留到 output
原生调用返回，且原生 recycler 返回。同步提前 recycle 时，output 尚未返回，
不能减为零；原生 recycle 内部已重新分配同一 EB 地址时，新发送占用另一 slot，
旧 wrapper 返回只处理其原 slot。原生返回码原样传递，错误本身不减少存活数。

recycle 后不读 EB 或 metadata。扫描、计数和 slot 变更在短临界区中；driver、
分配、释放都在区外。普通 RX/TX recycler wrapper 和可达 helper 位于 IRAM，
账本位于 internal memory。原生没有经过回收的缓存帧继续保持 tracked。

最多 64 个记录。首次 TWT 管理帧发送分配 512 字节，不发送 TWT 时没有该分配；
账本跨 runtime/driver restart 保留至设备重启，快照显示 `reserved_bytes`。
静态记录 24 字节，C5 单核构建的 lock 无独立存储；不改变已有 30 个跟踪框架
静态对象及 32 字节 EAP stop 记录。真实 heap allocator 开销及静止态 largest
block/internal/PSRAM 比较仍为 not-run，512 字节是请求分配大小。

OOM、容量耗尽、活动 EB 重复登记、revision 耗尽均保留首个 boot 级 fault；
不回绕、不清零伪造可用状态，也不停止转交已经分配的 SDK 帧。fault 后 counts
只能表示已跟踪子集，任何零值都不能作为完整 drain 证据。没有外部 mark-done
或 reset 接口；SDK 本身非法重复 free 不属于该观察器能够修复的内存损坏。

内部 `management_tx` 快照包含 revision、tracked、output/recycle 调用数、
reserved bytes、fault。probe 的 null/data TX、timer rearming、原生队列与默认
事件队列排空仍必须独立处理；本项不会调用 lane 的 retired/event-fenced 消费接口。
