## 实现

`esp32_mquickjs_wifi_eap_config.c` 持有一份 sealed profile 独立引用，以及至多一个
正在控制的操作引用。没有 JS/context 指针，没有新的秘密副本或单独预算器。
status 只含修订号、configured/busy/closing 与两种耗尽标志。

- configure 调用方须在任何 getter 前取得 revision；完成捕获和结果预分配后，
  replace 校验相同 revision、非 closing、无在途控制、Radio 无 SDK binding。
  retain 新候选后才交换配置，在 critical section 外释放旧引用。过期提交不能
  覆盖重入调用提交的新配置，也不能减少新配置的引用。
- begin 以精确 revision 预留单控制 token，并固定操作所用的 profile。token
  包含独立 boot-scoped 64-bit identity、当时 revision 与 action。任何公开 SDK
  控制必须先经 begin；仅超时或 Future 终态不授权 finish，原生工作须已返回。
- finish 校验完整 token，允许 runtime 已 closing 时旧操作收尾；重复、过期或
  action/revision 被改动的副本不释放另一操作的引用。仅 CLEAR action 且 Radio
  已无 SDK binding 才能丢弃配置。SDK 退休失败时可以结束已返回的控制引用，同时
  保留配置和独立 SDK 借用，供下一次关闭重试。
- revision 和 control identity 均不回绕复用。revision 耗尽拒绝 replace/open；
  identity 耗尽拒绝新控制。begin_close/finish_close 仍可执行必要释放，不靠重新
  初始化计数器清除故障。
- runtime 初始化打开空 owner，并消耗新 revision。退出先 begin_close，失效尚未
  提交的捕获并阻止新控制；忙操作须完成，再沿既有断连/Radio 清理退休 SDK 借用，
  最后 finish_close 释放配置。未启用、仅配置的凭据也会在 runtime 退出时清零。

config mutex 只保护原生元数据；Radio 查询在其外，free/wipe 在其外。嵌套 retain
固定顺序为 config -> profile，retain 不分配、不调用 SDK。Radio 查询和 commit
间若另一个公开控制先 begin，busy 门槛会拒绝 commit。直接调用 SDK/Radio 绕开
此 owner 的内部路径不享有该保证；正式公开入口尚未接入，不能宣称完整 API
并发验证已完成。
