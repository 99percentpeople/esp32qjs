# DPP bootstrap 所有权与凭据事务

基线 firmware `d7db8d1`、固定 SDK `fff9895c82d744c7237be8847347bdd1b07c6643`。
这是 DPP 的原生前置批次，尚未接入 Radio/Session/Future，也未注册公开 API。
继续使用 SDK 的 Wi-Fi events，不恢复已删除的公开 DPP callback 契约。

## 确认的问题与修复

固定 SDK `esp_dpp.c` 将 bootstrap 设备信息和私钥拼进命令字符串，随后
`get_param` 按空格截断；设备信息可改变其他参数的解析。队列携带含私钥的
堆命令，但 deinit 的 timer 取消列表没有这个命令，普通 free 也不清零。

现在 SDK 接口先把最多五个互不重复的 channel、key 和 info 完整验证到临时
结构，再读取 MAC/分配作业/排队。错误项不再被跳过；失败不修改当前 bootstrap
参数。任务只携带不复用的 64-bit 数字 ticket，所有权记录单独持有按需堆对象。
重复排队和正在协商时的替换拒绝；deinit 在 Wi-Fi/eloop task 精确取消排队项后
才清零释放。取消数量不符合预期时保留义务，旧 ticket 不可解引用新对象。

新增内部 structured bootstrap helper 直接调用 SDK 的 keygen/URI 生成逻辑，
不再解析拼接命令。info 最多 128 个可打印 ASCII 字符，允许空格、拒绝 `;`；
`name key=...` 仍只是完整设备信息。SDK 头文件的“raw 32-byte key”与实现不符：
`dpp_set_keypair -> crypto_ec_key_parse_priv` 消费 DER，官方 enrollee 示例先把
P-256 scalar 包进 SEC1，再转成 hex 传入。这里保留实际 SDK hex-DER 输入，
最多 256 DER 字节，要求偶数个有效 hex 字符；具体密钥由既有 crypto 验证。
不把 raw scalar 直接当 DER。临时 key、整个 job 与内部 key 副本在异常和正常
释放时清零。移除 bootstrap raw-private-key hexdump 与接收 connector 原文日志；
未据此宣称其余 DPP crypto/日志分支已完成全面秘密审计。

旧 bootstrap 在新 URI 构造和事件交付失败时保留。新状态在零等待 URI event
发布前提交，发布失败恢复旧值；发布成功后释放旧 bootstrap。这里仍是 SDK
事件交付，尚无框架 retained-result owner；观察队列饱和时必须可查询的独立
控制终态和完整 Future 交付继续属于下一批工作。

配置处理现在拒绝超长 SSID、access key、C-sign key 与不完整 DPP row，避免把
被截断的密钥当成有效结果。已安装配置的精确比较包括 connector、AKM/channel、
两种密钥的长度/每个字节和 expiry。新的配置完整分配成功才替换旧配置；
无效参数或第 N 次 allocation 失败保留原配置和 driver ready 标志。

GAS response 的 legacy clear 延后到 event 发布成功，不再提前删除原 DPP store。
跨 event unlock 窗口用不回绕的 revision 核对配置修改，避免只比较旧指针产生
ABA；并发应用选择优先。set_config 的 driver 标志在同一锁内更新，避免后来的
clear 被较早 setter 的迟到标志覆盖。接收端分配先检查 size_t 加法与 uint32
长度转换。所有这些修改只在 build-local `esp_dpp.c` / `dpp.c`，共享 SDK 未改。

## 构建和验证边界

新增独立 `build/wireless-contexts/c3-dpp`，从原 C3 context 复制并只改变 identity
与 DPP 开关/配置数量，保留原 context；清单和 hash 见
`build/w08-dpp-input-context.json`。本批检查 C3 DPP 启用与关闭分支，完整 C3/S3/C5
矩阵留在阶段节点。源码确认的问题摘要见 `build/w08-dpp-input-before.json`；
编译与实际 archive 证据见 `build/w08-dpp-input-evidence.json`。

新增两组调用生产代码的 deferred fixture：严格输入、取消失败后缀、旧 ticket、
事件失败、job/URI OOM 和秘密释放；配置密钥/expiry 变更、每次安装 allocation
失败、非法长度和关闭期间修改。仅 AST，未导入、编译或执行 fixture。
这是源码修复和生产编译证据，不是动态复现、完整调度或 RF 验收通过。

## 剩余 DPP 范围

- retained URI/config/failure owner；控制完成先于有界 metadata 观察。
- 原生 init/partial-failure/deinit、RX/TX/ROC/timer 的精确存活和退休。
- 无 cookie/8-bit TX op 与 ROC context 的迟到完成隔离，退出后才允许复用。
- Radio/helper 准入、Station/AP 配置/信道交接及 worker/runtime 清理。
- 公共 enrollee options/Session/Future/watch、凭据选择/安装与连接安全契约。
- 全部 GC/OOM/队列/调度/实机和安全资格验证。

DPP 关闭配置的编译通过不代表能力已经实现或设备不支持。其余 Wi-Fi 工作清单
保持；集中运行与实机在 Wi-Fi API 完成后，长 soak 在 BLE API 也完成后。
未刷写、串口操作、提交、推送或修改根仓库 gitlink。
