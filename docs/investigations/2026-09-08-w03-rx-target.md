## 本地 SDK 读取契约

依据固定 SDK `fff9895c82d744c7237be8847347bdd1b07c6643` 的
`esp_wifi_types_native.h`、`esp_wifi_types_generic.h`、`esp_wifi_he_types.h` 与
`docs/en/api-guides/wifi-driver/wifi-modes.rst`，仅接受原生 promiscuous callback
交付的已知类型 buffer。它不是任意指针有效性检查，也不适用于 CSI hdr 指针。

| 情况 | 实现 |
| --- | --- |
| 未知 callback type、NULL buffer/output、地址加法溢出 | 返回独立 span status；未知 type 在读取 metadata 前拒绝 |
| 已知 callback type | 编译断言 metadata/payload 偏移；memcpy 到对齐的 native metadata，避免直接解引用未对齐 bitfield 指针 |
| MISC/MIMO metadata-only | 只复制 metadata，bytes=NULL、readableLength=0；即使报告长 sig_len 也不读取 payload |
| C3/S3 legacy payload | 使用该原生 callback 契约声明的 sig_len；不是把任意 SDK 长度通用地当作 allocation length |
| C5 HE payload | 使用独立 dump_len；零值或大于 sig_len 时拒绝，不回退读取 sig_len 的尾部 |
| CRC 错误帧 | 保留 rx_state；仍可有结构可解析的 MAC header，不把 parser 成功当成 FCS 正确 |
| SDK type 与 FC type 不一致 | 分别保留原生类型和实际 header，header_type_matches=false |

输出分为无指针的 driver metadata/header 和 callback 内短暂有效的 bytes view。
后续 broker 必须在 SDK callback 返回前复制有限 payload，不能把整个带指针 view
排入队列。metadata 保留原生 RSSI/noise/channel/timestamp/length/rx_state；legacy
显式 HT 字段仅在 sig_mode=1 时可用，HE 保存原始 SIG/format/rxend facts。
完整 PHY 规范化、RX 时钟扩展、FCS 表示仍待完成。字段存在不等于 RF 证据。

## 原生过滤边界

过滤器不分配内存、不调用 SDK/JS、不读取 view.bytes，返回单个明确的拒绝原因。
配置在 subscriber 准入后应不可变，每个 subscriber 独占一个零初始化状态，调用者
负责串行化 evaluation/reset；此 helper 本身不提供 callback 生命周期或并发锁。

- 先验证全部配置：类型 mask 仅 4 bit；source/destination/BSSID 各最多 8 个 MAC；
  sampleEvery 为非零 u32，maximumRateHz 为 0（关闭）或 1–1000000。
  无效配置在遍历数组前拒绝，不改变抽样状态。
- 类型、可选 subtype、MAC、RSSI 使用复制的元数据。地址列表内是 OR，三种地址
  角色间是 AND。不存在的地址不匹配全零 MAC；DS 地址角色来自实际 MAC parser。
- validOnly 要求 rx_state=0、完整已解析 header 和一致类型；MISC/短头/未知布局
  不满足此条件。validOnly=false 可保留错误或 metadata-only 观察，但不能凭空
  补地址。该检查不验证帧体、密码学或 FCS 内容。
- subtype 过滤需要一致且可读取的 FC；只有地址过滤要求完整已解析 header。
  启用的空类型/subtype mask 不匹配任何包，空 MAC 列表表示不限制该角色。
- 静态条件合格的第一包及以后每 N 包抽样；phase 在 N 内循环，避免累计计数回绕
  改变抽样周期。静态过滤失败不推进 phase；限速拒绝发生在抽样之后。
- 限速使用调用者提供的单调 callback-time u64 微秒，不使用回绕的原生 RX
  timestamp。最小间隔为 ceil(1000000/rate)，时间倒退拒绝，不经减法下溢放行。
  新 capture run 必须重置状态。通过过滤后，即使后续 pool/queue 满，仍消耗本次
  间隔，以约束回调复制压力；交付计数由后续 Monitor 另行维护。

这些是内部生产契约，尚未发布正式 Monitor 参数/defaults/类型或能力广告。
现有 CSI filter 未切换到此 helper；CSI 的 first-word/channel-estimate 判断不能
被 Monitor 的 MAC header validOnly 替代。
